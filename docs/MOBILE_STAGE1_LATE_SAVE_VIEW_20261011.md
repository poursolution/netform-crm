# [단계 1] 늦게 도착한 저장 응답의 입력 창 덮어쓰기 방지

## 한 일

견적 요청을 저장한 뒤 다른 입력 창을 열면, 늦은 성공·실패 응답이 새 창의 내용을 지우는 오류를 합성 서버로 재현했다. 방문 결과와 일정 변경 저장에서도 같은 문제가 확인돼 세 저장 경로에 동일한 보호를 적용했다. 저장을 시작한 입력 영역이 여전히 열려 있을 때만 결과·오류 화면을 그린다. 사용자가 이동해도 승인한 저장의 서버 확인 및 복원 정보 처리는 유지한다.

## 바뀐 파일

- `mobile-fields.js`: 견적 저장의 지연 성공·실패 응답이 다른 입력 화면을 교체하지 않도록 보호.
- `mobile-entry.js`: 방문/통화 결과 및 일정 변경 저장에 같은 보호 적용.
- `mobile.html`: 두 모듈 캐시 버전 갱신.
- `verify-mobile-visit-quote-flow.cjs`: 늦은 응답·원래 건 재진입·단계 변경 검사 추가. 총 15개.
- 이 문서, 진행상태, 후보 manifest·누적 패치.

## 추가·바꾼 데이터 필드

서버·복원 저장소 필드 추가 없음. 저장 시작 시 그려진 입력 영역의 DOM 참조로 화면이 바뀌었는지 확인한다. 디자인·HTML 구조·입력 항목 변경 없음.

## 점검표 통과 / 미통과

- 실제 모바일 앱 + 합성 RPC/큐 통합 15개 통과. 견적·방문·일정 변경의 늦은 성공/실패 후 다른 창의 입력 보존을 확인했다. 실패 후 원래 건으로 돌아가도 기존 활동 요청 번호를 재사용한다.
- 견적 안전·복구 18개, 모바일 요청 복구 5개, PC·모바일 일정 회귀 9개 통과. 이번 실행 브라우저 검사 총 47개.
- 단계가 저장 전에 바뀌면 첫 견적 RPC를 보내지 않는다. 응답 대기 중 바뀌면 오래된 단계 값을 화면에 적용하거나 다음 업무를 새로 보내지 않는다. 불명확한 저장 결과는 임의 재전송하지 않는다.
- 운영·실계정·실제 모바일 기기 검증은 하지 않았다. 외부 네트워크 차단 및 합성 자료 검사다.

## PC와 다른 점

이번 수정은 모바일의 비동기 저장 화면 보호다. PC 저장·견적 계산·디자인은 수정하지 않았다.

최신 공개 master는 `0b7852e8824abf3740bb12b10b227ee7e3f84c59` (#594)다. 직전 `939a1be` 이후 Claude 견적 제출금액 기능이 추가됐고, 누적 후보와 `crm.html`, `deal-detail-v3.js`, `pc-manager-transport.js`, `pc-error-state.js`가 겹친다. **기존 기준 소스에 대한 패치 검사는 최신 master 재통합을 대신하지 않는다.** 이번 통합 브라우저 검사는 기존 기준 앱과 후보 파일 조합이다. 최신 master에 대한 재통합·견적 서버 계약 검증이 남아 있다. 이전 보고서의 “새 견적 RPC 정의 없음”은 당시 커밋 기준이며 현재 master 전체에 대한 판단으로 쓰면 안 된다.
