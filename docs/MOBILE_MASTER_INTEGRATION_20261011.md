# [단계 1] 최신 master #594와 모바일 기능 후보 재통합

## 한 일

기준 커밋을 `5fe1b714dff4c0b7efc963066b45242d96fa4d10`에서 `0b7852e8824abf3740bb12b10b227ee7e3f84c59`(#594)로 올렸다. 기존 후보·이전 기준·최신 master를 3방향 비교해, Claude의 견적 제출금액 기능과 후보의 일정 보존·응대 및 요청 복구를 모두 유지했다.

## 바뀐 파일

- `crm.html`: 최신 견적 제출금액 함수·화면 코드 및 `quote-amounts.js` 로딩 유지. 기존 후보의 일정·문의 저장 도우미 연결 유지. 변경 모듈 캐시 이름 갱신.
- `deal-detail-v3.js`: 최신 제출금액 진입 동작과 후보의 저장·복원 기능 결합. 새 디자인 작성 없음.
- `pc-manager-transport.js`, `pc-error-state.js`: 최신 `crm_quote_submit_confirm_v1` 허용 목록·오류 이름과 후보 함수 목록을 함께 보존.
- 기존 로컬 `verify-*.cjs` / `run-*.cjs` 중 이전 기준 경로를 사용하던 14개와 패치 생성기의 기준 경로 갱신.
- `verify-quote-master-integration.cjs`: Claude의 최신 브라우저 검사 원문을 그대로 실행하되 파일 제공 경로를 후보+최신 기준으로, 브라우저 실행 파일만 로컬 Edge로 연결. 검사 조건은 변경하지 않았다.
- 이 문서, 진행상태, manifest·누적 패치. 통합 전 4개 파일은 `integration-0b7852e/before-integration.zip`에 보관.

## 추가·바꾼 데이터 필드

이번 재통합에서 새 서버 필드·SQL·RPC·권한을 설계하거나 설치하지 않았다. 최신 master의 견적 계산·엑셀 모듈·SQL은 그대로 참조한다. 모바일 허용 목록에 견적 제출 확정 RPC를 임의 추가하지 않았다. 모바일 견적 v3 연결은 별도 단계다.

## PC와 다른 점

최신 PC 디자인·견적 흐름을 재해석하지 않았다. 견적 계산도 Claude 모듈 원문 그대로다. 후보의 기능 보호를 추가한 통합본이며 운영 배포본은 아니다.

## 질문·남은 연결

새 디자인 결정 없음. 로컬 기준 재통합은 완료했다. 서버 마이그레이션 설치·기능 게이트 활성화·실계정 검증·모바일 견적 v3 계약 연결·GitHub 업로드 및 배포는 남아 있다. 이번 작업은 이들을 실행하지 않았다. 8766 시안과 전체 단계 1 완료 여부는 변경하지 않았다.
