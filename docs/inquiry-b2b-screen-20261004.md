# 협약문의 B2B 완료 처리 연결

- 전달된 `design_handoff_b2b/협약문의 B2B.dc.html`의 목록·처리 패널 규격을 사용한다. 기존 공통 제목·필터·공사 문의 렌더러는 보존한다.
- 원래 서버 조회 범위와 공통 필터를 적용한다. 협약문의의 열린 건과 협약완료/해결완료/종결을 나누고 접수 오래된 순으로 표시한다.
- 과거 배드핏·실주·영업전환·영업건 연결 건은 자동으로 재개하지 않는다.
- 실제 원문·연락처·채널을 표시한다. 시안의 예시 업체는 운영 데이터에 넣지 않는다.
- 결과 선택만으로 저장하지 않는다. 명시적 처리 완료 → 검증된 서버 ACK 이후 완료 목록 이동 → 다음 문의 선택. 저장 실패 시 입력 유지, 재시도는 기존 요청 ID 유지.
- 종결은 사유 필수. 협약완료·해결완료는 메모 선택. 서버의 기존 성공 영수증 재전송은 유지한다.
- 기존 담당자·관리자 권한을 유지한다. 조재연 계정은 확인 시 접속 승인 정보가 없어 권한 부여 확인을 별도 요청했다. 자동 승인·자동 재배정은 수행하지 않는다.
- CRM 저장은 즉시 완료되고 잔디 연동 시트 반영은 기존 대기열에서 후속 처리한다. 실제 시트 반영 완료 전에 동기화 완료로 표시하지 않는다.
- 실제 고객 건은 검증용으로 완료 처리하지 않았다.

## 검증

클라이언트·DB·조회 범위 집중 테스트 10개 통과. 가상 데이터 브라우저에서 종결 사유 필수, 자동 갱신 중 초안 유지, 실패 시 목록 유지, 성공 ACK 후 다음 문의와 완료 이력 표시를 확인했다.

운영 DB에 `inquiry_b2b_close_reason_required` 적용 및 직접 호출 권한 차단을 확인했다. n8n 기존 응대 입력폼/추출 노드에 같은 사유 규칙을 반영했다.
