# OS B2C 접수 ↔ 영업 CRM 직접 연결 (검토안, 2026-11-06)

OS 업무페이지의 B2C 아파트 접수 화면이, 담당자 본인의 CRM 로그인으로 문의를 보내고 진행을 읽기 위한 서버 함수입니다.
`docs/OS_B2C_BRIDGE_20261021.md`의 5번(미연결 항목) 중 전송 경로, 진행 조회, 담당 반영을 채웁니다. `os-b2c-bridge.js`는 바꾸지 않았습니다.

## 추가되는 것

| 이름 | 하는 일 | 권한 |
|---|---|---|
| `crm_os_b2c_capability_v1()` | 이 계정이 연결을 쓸 수 있는지 확인 | 로그인 사용자 |
| `crm_os_b2c_handoff_v1(p)` | 문의 만들기 또는 기존 문의에 연결 | `admin`, `consultation` |
| `crm_os_b2c_owner_change_v1(p)` | OS에서 바꾼 담당을 문의에 반영 | `admin`, `consultation` |
| `crm_os_b2c_status_v1(p_ids)` | OS에서 보낸 건의 진행 읽기 (한 번에 50건까지) | `admin`, `consultation` |
| `crm_security.os_b2c_links`, `os_b2c_link_events` | 접수번호 ↔ 문의 연결표, 변경 기록 | 표 직접 접근 없음 |

기존 표의 구조와 기존 함수는 바꾸지 않습니다. 새 문의를 넣고(`public.inquiries`), 담당 변경 때 그 문의의 담당 칸과 상태만 바꿉니다. 배정과 담당 변경은 `public.assignment_history`, `crm_security.inquiry_audit_events`에 CRM 직접 배정과 같은 형식(`direct_assign`, `direct_reassign`)으로 남깁니다.

## 규칙

- **중복 생성 방지:** 전송 키는 `os-b2c:접수번호`입니다. 같은 키로 다시 보내면 새 건을 만들지 않고 처음 결과를 돌려줍니다(`replayed`).
- **이미 있는 문의:** 전화번호와 브랜드가 같고, 열려 있고, 휴지통이 아니고, 30일 안에 접수된 문의가 있으면 새로 만들지 않습니다. 그 문의에 연결하고 `duplicate_of`를 돌려줍니다. 기존 문의의 내용과 담당은 덮어쓰지 않습니다.
- **담당:** CRM 직접 배정과 같은 기준입니다. 로그인이 승인된 `rep` 계정 중 이름이 정확히 한 명과 맞을 때만 담당으로 잡고 상태를 `배정완료`로 둡니다. 없으면 담당을 비운 채 `접수`로 만들고 `owner_unmatched`를 돌려줍니다. OS 화면은 이때 "CRM 담당 미지정"으로 안내합니다.
- **CRM 화면 표시:** CRM 상세는 `raw`를 한글 칸 이름으로 읽습니다. 같은 값을 `현장명`, `고객유형`, `건물유형`, `단지개요`, `관리사무소`, `상담채널`, `공사유형`, `유입경로`, `전화응대자`, `전화 응대자`, `문의내용`, `특이사항`으로도 넣습니다. `source_channel`에는 OS 유입경로(없으면 `OS B2C 접수`)를, `channel`에는 OS 상담채널을 넣습니다.
- **담당 변경을 막는 경우:** 종결된 문의(`INQUIRY_CLOSED`), CRM에 원래 있던 담당 지정 문의(`EXISTING_OWNER_IN_CRM`), 영업건이 만들어진 문의(`DEAL_OWNER_IN_CRM`), 맞는 사용자가 없는 경우(`OWNER_NOT_FOUND`)입니다.
- **돌려주는 값:** 단계, 결과, 담당, 다음 연락일, 최근 응대, 견적 금액입니다. 전화번호와 주소는 돌려주지 않습니다.
- **읽기 범위:** 연결표에 있는 건만 읽습니다. 접수번호로 다른 CRM 문의를 찾을 수 없습니다.
- **접수 시각:** `received_at`은 CRM이 받은 시각입니다. OS 접수 시각과 1차 연락은 `raw`에 보존하며, 첫 응대 집계에는 넣지 않습니다.
- **비밀 열쇠:** 쓰지 않습니다. 화면에는 CRM 화면에도 공개된 값만 들어갑니다.

## 정해 주셔야 할 것

1. **권한:** 지금은 `admin`, `consultation`만 허용합니다. OS 담당자의 실제 CRM 역할이 다르면 바꿔야 합니다(미확인).
2. **로그인 방식:** 화면은 이메일·비밀번호 로그인만 지원합니다. Google로만 로그인하는 계정은 비밀번호를 설정해야 합니다.
3. **기존 문의 판단 기간:** 30일이 맞는지 확인이 필요합니다.
4. **담당 이름:** OS 담당 이름과 CRM 사용자 이름이 똑같아야 담당이 잡힙니다.
5. **읽기 범위:** `crm_security.can_inquiry`는 `rep`, `consultation`에게 본인 담당 문의만 보여 줍니다. OS 담당자가 다른 사람에게 배정한 문의를 CRM에서 직접 열 수 있어야 하는지 정해 주세요. 진행 조회(`crm_os_b2c_status_v1`)는 이 제한과 별개로 동작합니다.
6. **담당 기준:** 임원처럼 `rep`이 아닌 계정을 OS에서 담당으로 고르면 CRM에는 담당 미지정으로 들어갑니다. 이 기준이 맞는지 확인이 필요합니다.

## 소스로 확인한 것

- **바로 열기:** 화면의 `#p=pipe&deal=`, `#p=inq&sel=`는 `pc-router.js`, `index.html` 규칙과 맞습니다. 실제 열림은 설치 후 확인합니다.
- **칸 이름:** 넣고 읽는 칸은 `tests/fixtures/dashboard-read-schema.sql`에 모두 있습니다. 운영 DB에 직접 대조한 것은 아닙니다.
