# Claude 인수인계: 승인 모바일의 남은 기능 진입 3곳

2026-10-11 · `poursolution/netform-crm` · 승인 원본과 로컬 구현을 읽기 전용으로 대조한 결과다. 이 문서를 위해 화면·스타일·기능·SQL을 변경하지 않았다. 아래 행 번호는 이 검토 시점의 소스 기준이다.

## 기준과 범위

- 전체 모바일 기준은 사용자 제공 `Pipeline redesign proposal43.zip`의 `CODEX_HANDOFF.md` → `CODEX_DESIGN_GUIDE.md` → `Codex 모바일 디자인 가이드 · 예시.dc.html` → 폴더 1~5 순서다. 가이드 20절의 확정 결정이 앞선 그림·문구보다 우선한다.
- 실제 `Pipeline redesign proposal44.zip`에는 `design_handoff_quote_v3`가 들어 있다. 이 묶음의 견적 변경을 계정 메뉴·오늘 동선의 새 디자인 승인으로 해석하지 않는다.
- 기존 기능이 사라진 진입은 해결 대상이다. 그러나 검사 통과를 위해 예전 모바일 화면을 다시 노출하거나, 새 배치·버튼·메뉴를 임의로 만들지 않는다.
- **서버 3개 SQL의 설치·검증·활성화와 아래 화면 진입 문제는 별개다.** SQL 설치만으로 해당 화면·동작이 연결되지 않는다. 이 문서는 서버 설치 완료 여부를 재판정하지 않는다. 서버 선행조건과 후속 실행 상태는 [문의 D 배포 선행조건](MOBILE_INQUIRY_D_DEPLOYMENT_BLOCKER_20261011.md)을 따른다.

## 1. 비밀번호 변경

**원본 근거**

- `CODEX_HANDOFF.md:70`: 영업사원 실제 계정 메뉴·권한 확인은 아직 정해지지 않은 항목이다.
- 전체 묶음 `README.md:32`에도 실제 계정 메뉴가 검토 전으로 표시돼 있다.
- 최신 A~H 원본에는 비밀번호 변경 진입이 없다. 상단 종 알림은 계정 메뉴로 정의되지 않았다.

**현재 구현과 보존된 API**

- `mobile.html:1301`에 예전 `.home-bar`의 비밀번호 변경 버튼이 남아 있지만 승인 셸은 그 헤더를 렌더하지 않는다.
- `mobile-guide-shell.js:147`의 `show()`는 승인 프레임을 사용한다. 승인 셸에 비밀번호 변경 동작 분기가 없다.
- `account-password.js`의 `CRMPassword.open()`과 기존 비밀번호 검증·저장·민감 입력 정리 기능은 보존돼 있다. 기능 엔진 존재는 실제 진입 완료를 뜻하지 않는다.

**필요한 결정**

승인 계정 화면에서 비밀번호 변경을 여는 정확한 원본 슬롯과 대상 화면을 확정해야 한다. 알림 종을 다른 용도로 바꾸거나 예전 헤더를 복원하지 않는다.

**검증 요건**

`tests/account-password-browser.cjs:94`는 실제 모바일에서 비밀번호 변경을 여는 경로까지 검사한다. 독립 대화상자의 성공만으로 이 검사를 대체하지 않는다. 원본 진입 확정 후 320/375px, 영업 전용·관리 겸용 계정, 검증 오류·저장 잠금·취소·계정 변경 시 입력 정리 검증을 유지한다.

## 2. 오늘 동선

**원본 근거**

- 최신 가이드 C 추가 정보와 `Codex 모바일 디자인 가이드 · 예시.dc.html:353`에는 **근처 현장** 행이 있다. 원본 예시는 선택 현장 주변 `3km · 4곳`이다.
- 폴더 `1_PC기준_대조/README.md:30`에는 주변 현장 지도를 PC 기능과 같이 처리하라는 기능 요구가 있다.
- `[목록 | 오늘 동선]` 전환과 지도 그림은 폴더 `5_디자인규칙_화면/CRM Mobile.dc.html:51~60`에 있다. 최신 A에는 이 전환 줄이 없다. 최신 가이드보다 우선순위가 낮은 옛 오늘 화면 전체를 복원할 근거가 아니다.
- `4_화면흐름/모바일 화면 흐름 · 영업사원.dc.html:92`의 근처 현장 그림도 주변 3km 흐름이다.

**현재 구현과 보존된 API**

- `mobile-approved-bc.js:37`은 기존 근처 현장 행에 `data-gs="more"`, `data-value="근처 현장"`을 연결한다. `mobile-guide-shell.js:198`은 현재 자료 발송 내역·영업 조건만 처리하므로 근처 현장 행은 미연결이다.
- `mobile-guide-shell.js:137`의 오늘 화면은 승인 A로 렌더한다. `MobileRoute.decorate()`를 호출하지 않는다.
- `mobile-route.js:27`의 `stopsToday()`, `order()`, `crm_site_geo_list_v1` 조회, 지도 엔진은 남아 있다. `decorate():93`은 옛 `.mr-tabs`와 지도 UI를 붙이므로 승인 A에 그대로 호출하지 않는다.
- 기존 오늘 동선은 오늘 방문지 전체의 순서를 계산하고 방문지 주변 5km 관계관리 현장을 추천한다. 선택 현장의 주변 3km 조회와 대상·범위가 다르다.

**필요한 결정**

최신 승인 화면에서 **오늘 방문 동선**을 여는 정확한 슬롯과 도착 화면을 확정해야 한다. 근처 현장 행은 기존 승인 슬롯이지만, 그 동작을 오늘 동선으로 바꾸어 같은 기능이라고 처리하지 않는다.

**검증 요건**

`scripts/verify-mobile-route-browser.cjs:34~36`의 실제 동선 진입을 유지한다. 원본 연결 후 오늘 방문만 포함, 사용자 선택 전 위치 요청 없음, 좌표 없는 현장 분리, 지도 실패, 번호 핀·순서, 추천이 일정 생성·변경을 하지 않음, 현장 상세 연결까지 검사한다. 근처 현장 조회나 순서 계산 함수만 통과시켜 전체 동선 검사 성공으로 대체하지 않는다.

## 3. 방문 결과 → 공사 시기 보완 → 견적 요청

**원본 근거**

- `CODEX_DESIGN_GUIDE.md:265~272`의 10절은 오늘 방문 카드의 결과 입력 → 맥락 이어받기 → 상담·사진 → 견적 요청 → 방문 완료·견적 요청·후속 일정의 개별 미리보기 → 저장 후 구분을 요구한다. 견적 요청 취소 시 방문 기록은 유지해야 한다.
- `2_입력_한번만/README.md:28`은 방문 일정의 날짜·현장·목적을 이어받고 해당 방문 일정 완료를 따로 확인하도록 한다. 같은 문서 41행에 전체 흐름이 있다.
- 최신 D 그림은 연락 결과·상담 내용·다음 업무의 통화 입력이다. 가이드 162행의 고객 정보 변경은 맨 아래 링크에서 **별도 화면**으로 이동한다. 예전 방문 시트와 고객 정보 펼침 칸을 그대로 노출하는 것은 이 원본을 적용한 결과가 아니다.

**현재 구현과 보존된 API**

- `mobile-entry.js:47`은 통화일 때 `MobileContactView.render()`를 사용한다. 88행은 승인 셸에서 `MobileEntry.open({ch:'방문'})`을 차단한다.
- 같은 파일 125행은 승인 D의 고객 정보 변경을 미연결 안내로 처리한다.
- `MobileFields.save()`와 `crm_deal_stage_fields_update_v1` 공통 저장 경로는 남아 있다. `mobile-fields.js:75`의 `quoteSheet()`는 예전 견적 요청 UI이므로 재노출하지 않는다.
- 승인 K-1의 입력·초안 기능과 실제 견적 요청 접수는 구분한다. `mobile-quote-review-model.js:23,65`는 아직 요청 저장을 허용하지 않는다. 견적 서버 계약은 [견적 모바일 서버 인수인계서](CLAUDE_QUOTE_MOBILE_SERVER_CONTRACT_20261011.md)를 따른다.

**필요한 결정**

가이드 10절의 방문 결과 입력·해당 방문 완료 확인·견적 요청 이어가기와, D의 고객 정보 변경이 사용하는 최신 승인 원본 상태를 확정해야 한다. 기존 통화 D를 방문용으로 임의 해석하거나 옛 방문·견적 요청 시트를 복원하지 않는다. 견적 요청 접수 계약이 미연결이면 입력 보존과 실제 접수 완료를 구분한다.

**검증 요건**

`scripts/verify-mobile-fields-browser.cjs:37`부터 실제 방문 진입을 검사한다. 원본 연결 후 정확한 영업건·원래 방문 일정 이어받기, 방문 기록과 방문 완료의 구분, 공사 시기 저장 ACK 후 반영, 실패 시 원문 보존, 견적 요청 취소 시 방문 기록 유지, 공통 PC 필드·저장 결과 일치, 후속 일정 중복 방지를 유지한다. RPC 함수 단독 성공으로 실제 방문→견적 흐름 검사를 대체하지 않는다.

## 검수 경계

이 문서가 기록한 3개 기능의 진입은 완료로 표시하지 않는다. 기존 검사 삭제·건너뛰기, 옛 UI 복원, 서로 다른 업무로 검사 대체, 모바일 전용 저장 계약 추가는 해결로 보지 않는다. 승인 원본과 공통 저장 계약이 정리된 뒤 실제 버튼부터 결과 저장·재진입까지 검증한다.
