# 승인 모바일 진입 연결과 남은 제한 — 2026-10-11

`poursolution/netform-crm`의 승인 원본과 배포 후보를 대조한 최신 기록이다. 과거의 ‘3개 진입이 모두 없음’ 판단을 대체한다. 추가 개선이나 새 디자인을 제안하는 문서가 아니다.

## 기준

- 사용자 제공 source43의 `CODEX_HANDOFF.md` → `CODEX_DESIGN_GUIDE.md` → 예시 그림 → 폴더 1~5를 함께 확인한다. 최상위 그림에 없는 요소라도 하위 원본의 승인 구성을 먼저 대조한다. 서로 충돌하는 내용은 가이드 20절의 확정 결정을 우선한다.
- source44의 견적 v3 범위는 그대로 보존한다. 견적 자료를 계정 메뉴의 임의 추가 근거로 사용하지 않는다.
- 원본에 있는 진입은 기존 공통 기능에 연결한다. 새 메뉴·배치·옛 모바일 헤더를 만들어 검사를 맞추지 않는다.
- 사용자 최종 지시는 승인 디자인의 GitHub 반영·배포다. 새 계정 메뉴 위치를 반복 질문하거나 범위 밖 개선을 시작하지 않는다.

## 비밀번호

source43 `CODEX_HANDOFF.md`와 README는 실제 계정 메뉴가 확정되지 않은 항목임을 명시한다. 승인 모바일에는 수동 비밀번호 변경 메뉴가 없다. 상단 알림 종을 계정 기능으로 바꾸지 않는다.

`account-password.js`의 `CRMPassword.open()`·`checkForced()`와 PC의 기존 비밀번호 버튼은 보존된다. 로그인 후 `phase1:profile`에서 `crm_my_credential_state_v1`이 임시 비밀번호 변경을 요구하면 기존 공통 강제 변경창이 열린다. 이는 새 모바일 계정 메뉴 구현과 다르다.

`tests/account-password-browser.cjs`는 다음을 검사한다.

- 공통 창 320/375/1280px의 검증 오류·현재 비밀번호 확인·문자 보존·서버 실패/성공·입력 삭제·포커스 복원·저장 중 Escape 차단·계정 해제.
- PC의 실제 수동 버튼 연결을 유지한다.
- 승인 모바일 320/375px, rep 전용/관리 권한 겸용 계정에서 A 화면과 구 헤더·임의 계정 메뉴 부재.
- 기존 로그인 이벤트 → 자격상태 RPC → 강제 변경창 → 로그아웃·계정 해제, 로그아웃 후 비밀번호 입력 재진입 차단.

집중 검사는 통과했다. 인증은 합성이며 실제 비밀번호를 변경하지 않았다. **모바일 수동 변경 메뉴는 미지원**이다. 폐기된 `.home-bar` 버튼을 요구하던 검사는 승인 화면과 충돌하므로 위 실제 인증 경계를 검사하도록 정정했다. 미지원 메뉴를 지원 완료라고 바꾸지 않았다.

## 오늘 동선

source43 전체 원본의 `5_디자인규칙_화면/CRM Mobile.dc.html`에는 `[목록 | 오늘 동선]` 전환과 지도 구성이 있다. 기존 오늘 화면 전체를 복원하지 않고 해당 원본 구성만 승인 A에 연결한다.

`mobile-route.js`의 기존 오늘 방문 대상·좌표 읽기·카카오 지도 엔진과 원본 동선 렌더러를 연결한다. 선택 현장의 근처 3km 조회와 오늘 방문 동선을 같은 기능으로 바꾸지 않는다. 오늘 동선의 근처 관계관리 추천은 기존 5km 기준이며 일정 추가·변경 권한이 아니다.

검증 범위는 실제 A의 전환 클릭, 오늘 방문 대상만 포함, 사용자 선택 전 위치 요청 없음, 좌표 미확인과 지도 실패, 번호 핀·순서, 추천의 업무 쓰기 0, 승인 상세 연결 및 한 쪽 최대 20건이다. 함수 호출만으로 진입 성공을 대체하지 않는다. 최종 집중 검사가 통과했다. 실제 A → 오늘 동선 → C → 뒤로, 담당 범위·오늘 방문·좌표 미확인, 명시 위치 클릭 전 요청 0, 원본 인라인 스타일과 일정 무변경을 확인했다. 변경 파일은 `mobile-approved-route-source.js`, `mobile-approved-route.js`, `mobile-route.js`, `scripts/verify-mobile-route-browser.cjs`이며 후보·체크아웃 두 사본이 일치한다.

## 방문 결과

가이드 10절은 방문 맥락을 이어받아 기록하고 견적 요청으로 이어지는 흐름을 명시한다. 이번 배포 후보는 원본 A/F/C의 방문 진입을 **승인 D의 동일 3칸·PC 공통 5결과**에 연결하고, 현재 활동 제목을 방문으로 표시한다. 새 입력칸·스타일·별도 방문 시트를 추가하지 않는다.

`mobile-entry.js`와 `mobile-contact-view.js`가 실제 열린 원일정의 ID·텍스트·KST 날짜·종류·고객 합의를 대조한다. 방문 기록만 저장했다고 원일정을 자동 완료하지 않는다. 저장 ACK 전 값 변경 없음, 잘못된 ACK와 실패 시 원문 보존, 동일 UUID 재시도와 계정 변경 후 투영 차단을 유지한다.

`scripts/verify-mobile-fields-browser.cjs`의 승인 방문 집중 검사 **14개**, 기존 승인 D 검사 **11개**가 통과했다. 실제 F 일정 행을 누르는 경로를 포함한다.

**미지원은 남아 있다.** 공사 정보 편집 UI와 실제 견적 접수는 승인된 별도 진입·보존 계약 미연결로 차단된다. 방문 기록 완료를 견적 요청 완료·원일정 완료·공사 시기 저장 완료로 표시하지 않는다. source44 K-1의 미전송 초안과 서버 접수 완료도 구분한다.

## PC 방문·견적의 서버 선행조건

앞서 승인한 서버 SQL 3개 설치·활성화와 추가 `sql/inquiry-milestone-preserve-v1-20261011.sql`은 별개다. 추가 SQL은 로컬 실제 SQL·합성 검사만 완료했다. 운영 설치는 자동 승인 검토에서 차단됐고 명시 승인 대기이며, 이 문서 작업에서는 실행하지 않았다.

이 계약은 기존 PC 방문·견적 입력을 일정 보존 방식으로 저장한다. 공통 일정의 권한·부모 잠금·토큰을 재사용하고, 기존 next_actions/schedules를 취소·완료·교체하지 않는다. 최초 응대·연결·적합 판단을 추정하지 않고 발송된 견적 버전도 수정하지 않는다. 예정 일정과 사실 저장이 나뉘어 성공한 경우에는 영수증과 원 요청 번호로 남은 저장만 복구한다.

미설치 상태에서 보호를 켠 채 배포하면 PC의 기존 방문·견적 저장이 거절된다. 데이터 보존에는 안전한 거절이지만 기존 기능 유지 완료는 아니므로 **해당 선행조건 해결 전 병합·운영 배포 보류**가 맞다. 옛 교체형 명령으로 우회하거나 승인 없이 서버를 설치하지 않는다.
