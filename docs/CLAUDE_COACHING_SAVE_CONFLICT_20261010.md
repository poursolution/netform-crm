# 코칭 저장 충돌 방지 · Claude 후속 연결

기준: netform-crm master `f5672bca10d028ce439204841b263a5b5602616e` (#545).

## 변경 범위

같은 담당자·주차의 관리자 한마디를 편집하는 동안 다른 관리자 또는 KPI 요청이 원문을 변경하면, 이전 화면의 저장이 그 내용을 덮어쓰는 문제를 방지한다. 현재 코칭 창, 이전 담당자 창, 관리자 한마디 입력과 완료 전환은 `crm_rep_manager_comment_save_v2`를 사용한다. 기존 표·권한·목록 위치·디자인은 유지한다. 알림·n8n 실행은 추가하지 않는다.

- 서버 입력 `expected`: 새 글이면 명시적 `null`, 기존 글이면 `{updated_at, comment, status}`. 기존 행과 모두 일치하는 경우에만 갱신한다. 같은 담당자·주차가 이미 생긴 경우 새 글 쓰기도 충돌한다.
- 서버는 담당자 이름이 활성 계정 한 개에만 대응하는지 확인한다. admin·branch 쓰기 권한은 기존 v1과 같으며 일반 영업사원·미로그인·anon 권한을 확대하지 않는다.
- 입력 창의 기준은 편집 시작 시 고정한다. 조회 캐시가 바뀌어도 작성 중인 초안의 기준을 바꾸지 않는다. 자기 창의 업무 요청 추가는 원문이 정확히 보존된 경우에만 기준을 갱신한다.
- 서버가 거절하면 기존 실패 안내로 초안을 유지한다. 자동 재시도·자동 병합·기존 v1 재시도를 하지 않는다. 서버 성공 응답의 담당자·주차·본문·상태·저장시각 검사는 유지한다.

## 배포

1. `sql/20261009191116_coaching_comment_compare_and_save.sql` 적용. 새 함수 한 개이며 새 표·칼럼·데이터 이관은 없다.
2. 기존 `crm_release_manifest_v1`에서 v2 함수 존재 확인. `CRM_RPC_ALLOW`, 오류 이름도 같은 PR에 포함했다. `OpsStore.has`가 기존 CRMRelease 게이트를 거친다.
3. 필수 검사 후 화면 병합·배포. SQL 미설치 시 저장은 실패로 남으며 v1으로 우회하지 않는다.

로컬 PostgreSQL 호환 실행 검사에서 최초 저장 경합·오래된 본문/상태·완료 전환·KPI 요청 추가·권한·잘못된 기준·중복 담당자 이름을 검증했다. 브라우저 검사에서 캐시 갱신 중 초안 보존 및 기존 창/쪽 번호/저장 성공 경로를 확인한다. 이는 운영 DB 반영 완료를 뜻하지 않는다.

## 제한과 다음 단계

- 기존 v1과 호환 명령은 오래된 배포본의 호환성을 위해 유지한다. **구버전 클라이언트가 v1으로 직접 저장하는 것까지 차단한 변경은 아니다.** 운영 검증 시 새 배포본의 v2 호출 경로를 확인해야 한다. 향후 v1 종료는 호출자 점검 후 별도 진행한다.
- 응답을 잃어 서버 저장 여부가 불명확하면 성공으로 표시하지 않는다. 초안을 보관하고 다시 조회한다. 이번 변경은 요청 ID 기반 재전송 영수증 기능을 새로 만들지 않는다.
- 코칭 당시 대상 ID·완료 근거 저장은 아직 구현하지 않았다. 이번 PR은 그 선행 조건인 동시 수정 보호다. 숫자 감소나 날짜 변경을 실제 고객 업무 완료라고 판정하지 않는다.
- 과거 코칭에 없는 대상 ID를 현재 명단으로 복원하지 않는다. 대상 = 해결 + 미해결 + 근거 있는 제외 + 확인 불가로 대조하는 기능 계약은 `CLAUDE_COACHING_PAGING_20261010.md`를 따른다.
- 충돌 시 원문 비교·초안 복구 위치 및 코칭 대상 처리 결과의 표시는 Claude가 결정한다. Codex는 새 창·버튼·배치·색상을 추가하지 않았다.
