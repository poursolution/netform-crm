## 1. 위치 결정 5가지

| # | 문서의 질문 | 정한 위치 | 흐름 |
|---|---|---|---|
| 1 | 확인 항목별 결과 입력 · 미확인 | 오늘 업무 위 **받은 요청 카드**(`topHtml` 의 카드) 안, 결과 칩 줄 바로 아래 '추가 확인' 줄 | 항목마다 `필요 · 불필요 · 아직 확인 못 함` 칩 + 근거 한 줄. 기본값 = 아직 확인 못 함. 통화 연결 근거(`contact_proof`)가 생기기 전에는 회색 + "먼저 통화 결과를 저장" |
| 2 | 기록 입력과 전체 완료 분리 | 같은 카드의 아래 줄 | [판단 저장] = `complete:false` · [확인 완료] = `complete:true`(모든 항목이 필요 · 불필요이고, 필요 항목마다 업무가 연결됐을 때만 눌림). 카드 알약 = `응대 저장 · 확인 n개 남음`. '완료' 표시는 서버 `request_complete` 가 참일 때만 |
| 3 | 고객 회신 대기 | 응대 결과의 다음 업무 줄에 `고객 합의 · 내부 계획` 두 칩(영업건 상세에는 이미 있음 — day_zones §4-1) | '고객 합의'일 때만 '고객 회신 대기'로 표시. `검토중` + 날짜만 있으면 '내부 재확인 일정' |
| 4 | 요청자 결과 확인 | 오른쪽 '답 기다리는 중' 카드의 회신 줄 + 그 아래 '보낸 요청' 줄(#564) | 한 줄: `응대 완료 · 남은 확인 2(견적 · 방문) · 다음 10.13 내부 계획`. 고객 대기는 3번이 '고객 합의'일 때만. 확인되지 않은 대기를 지연 평가에서 빼지 않음 |
| 5 | 기존 일정 충돌 | 같은 카드 안 경고 한 줄(서버가 저장 전에 멈춘 경우) | `기존 일정 유지: <종류 · 날짜>` + [추가 업무로 등록] · [일정 변경 요청]. 기존 다음 할 일 · 방문 · 견적 일정은 화면에서 덮어쓰지 않음 |

이미 운영에 있는 것(다시 만들지 않음):
- 팝업 닫기 = 상태 변경 없음. 새 배정 팝업의 확인은 이 PC 에만 남고, 담당 확인(`seen`)은 카드를 실제로 조작할 때만 보냅니다(#558).
- 입력 중에는 팝업 대신 '알림 n건' 한 줄(#558).
- 부재 뒤 요청자 쪽 '고객 회신 대기' 알약 + 재연락 날짜 줄(F5 · #558).
- 견적 요청 완료 = 고른 목적마다 근거(F4) · 느린 목록 응답이 저장 결과를 되돌리지 않음(F3) — #558 + Codex #559.

## 2. 화면을 붙이기 전에 필요한 것 (계약 요청)

1. **`needed` 에 연결할 업무 후보 목록.** 서버는 `public.next_actions` 의 견적 · 방문 업무 번호를 요구하는데, 화면은 문의의 업무 번호 · 종류(action_type)를 갖고 있지 않습니다. `objectives_read_v1` 응답에 후보(번호 · 제목 · 종류 · 기한 · 상태)를 넣어 주시거나 후보 조회 함수를 알려 주세요. 화면이 번호를 추정하지 않습니다.
2. **견적 · 방문 업무를 새로 만드는 검증된 저장 길의 이름과 돌려주는 번호.** "필요"를 골랐는데 업무가 없을 때 그 자리에서 만들 수 있어야 합니다.
3. **고객 합의 / 내부 계획 구분을 저장할 칸.** 지금 영업건은 다음 할 일 글머리 `고객 약속: ` 으로 구분합니다. 문의 요청도 같은 규칙으로 갈지, 따로 칸을 둘지 정해 주세요.
4. **일정 충돌 때 선택(추가 업무 / 일정 변경)을 보낼 입력 칸.**
