# [단계 1] 늦은 음성·AI 결과로 인한 다른 현장 메모 오염 방지

## 한 일

공개 master `0b7852e8824abf3740bb12b10b227ee7e3f84c59`와 로컬 후보를 기준으로 기존 음성 입력·AI 정리의 입력 대상 보호를 점검했다. 새 기능이나 디자인을 추가하지 않았다.

실제 모바일 입력 창에서 합성 음성 결과를 지연시켰다. 다른 영업건을 연 뒤 이전 음성 결과가 도착하면 새 입력 상태의 메모가 이전 현장 내용으로 바뀌는 오류가 재현됐다. 수정 전 검사는 `deal/switch: speech contaminated draft`로 실패했다.

- 음성 결과는 시작 당시 입력 상태·계정·입력칸·열린 창이 유지될 때만 반영한다. 다른 화면으로 이동하거나 닫기·직접 수정·계정 변경 시 인식을 중단한다. 이미 시작한 저장의 입력도 변경하지 않는다.
- 인식한 문장은 기존 입력 이벤트로 초안에 보관한다. 창을 다시 열어도 같은 현장의 입력으로 이어진다. 음성 권한 오류 안내를 뒤늦은 종료 이벤트가 성공 문구로 덮지 않게 했다.
- AI 정리 응답은 원문이 그대로일 때만 반영한다. 새 입력 창이나 요청 대기 중 직접 수정한 문장을 덮지 않는다. 정상 응답의 기존 원문 되돌리기와 결과·날짜 제안 동작은 유지한다.

## 바뀐 파일

- `mobile-entry.js`: 영업건 음성·AI 입력 대상 확인, 음성 초안 보관과 종료 처리.
- `mobile-inquiry.js`: 문의 음성 입력에 같은 보호 적용.
- `mobile.html`: 위 두 스크립트 캐시 버전만 변경.
- `verify-mobile-input-assistance.cjs`, `mobile-input-assistance-result.json`: 실제 입력 창에 합성 음성·AI 응답을 연결하는 19개 검사.
- 본 문서·진행상태·검증 manifest·후보 패치.

## 추가·바꾼 데이터 필드

없음. 기존 sessionStorage 초안과 입력 이벤트를 사용한다. AI API 요청·응답 계약, 저장 명령, 데이터베이스, 권한은 변경하지 않았다. 음성 입력이나 AI 제안을 실제 응대·발송·일정 완료 기록으로 저장하지 않는다.
