# [단계 1] 모바일 견적 요청 입력·저장 진행 복원

## 한 일

기존 견적 요청 창을 닫고 다시 열어도 상담 내용·공사 시기·예정일을 이어받는다. 단계 정보 저장을 서버가 확인한 뒤 다음 업무 저장만 실패한 경우, 재진입 후에도 같은 큐 요청 번호로 남은 저장을 확인한다. 기존 방문 기록은 다시 만들지 않는다.

## 바뀐 파일

- `mobile-fields.js`: 계정·영업건별 초안 및 진행 상태 복원, 전송 전 저장소 확인, 확정된 필드 재저장 방지, 결과 미확인 재전송 차단. 저장 완료 뒤 기존 닫기 버튼이 작동하지 않던 조건도 수정.
- `operational-overlay.js`: 공용 MobileSaveJournal에 `quote` 종류 추가. 기존 로그인/대상 분리·손상 확인·로그아웃 정리 규칙 재사용.
- `mobile.html`: 캐시 버전 갱신.
- `verify-mobile-fields-safety.cjs`, `verify-recovery-journal.cjs`: 복구 및 계정 분리 검사.
- 이 문서·후보 manifest·누적 패치.

## 추가·바꾼 데이터 필드

서버 필드·SQL·RPC·권한 추가 없음. 브라우저의 기존 sessionStorage 복원 저장소에 `quote` 기록을 사용한다. 계정(auth_uid/user_id)·영업건 ID별로 메모, 공사 시기, 최초 예정일, 단계, 필드 전송 여부/확인 내용, 다음 업무 큐 등록 시작 여부/요청 번호를 보관한다. 서버 저장 성공으로 대신 취급하지 않는다.

## 점검표 통과 / 미통과

| 검사 | 결과 |
| --- | --- |
| 견적 저장·재진입 합성 브라우저 | 18개 통과 |
| 실제 MobileSaveJournal의 quote 저장/조회·계정/대상 분리·손상·용량·로그아웃 정리 | 통과 |
| 기존 모바일 요청 복구 회귀 | 5개 통과 |
| HTML 그리기 및 paint 함수 | 기준본과 동일 |
| 실계정·실제 모바일 기기·서버 알림 | 미검증 |

브라우저 검사는 외부 통신을 차단하고 실제 `mobile-fields.js`와 합성 RPC·큐를 사용했다. 새 페이지에서 이전 저장 상태를 주입하여 필드 재저장 없이 기존 큐 요청을 사용하는 것도 확인했다. 실제 저장소 직렬화·계정 분리는 별도 공용 모듈 검사로 확인했다.

서버가 확정 거절한 `22023/42501/PT409`는 다음 시도를 허용한다. 응답 유실·형식 불일치 등 **저장됐는지 모르는 경우**에는 필드를 다시 보내지 않는다. 현재 RPC에는 요청 영수증 조회가 없으므로, 이 경우 서버 확인이 필요하다. 큐 등록 시작과 요청 번호 보관 사이에 중단된 경우도 새 업무를 생성하지 않고 기존 전송 대기를 확인하도록 안내한다.

sessionStorage이므로 앱 종료·탭 소멸 후 영구 보관을 보장하지 않는다. 견적 요청 전체의 원자적 저장·자동 복구 완료가 아니며 새 일정 보존 기능은 계속 OFF다.

## PC와 다른 점

이번 보완은 기존 모바일 견적 요청 창의 입력 복원이다. PC 견적 v3 저장·계산을 재작성하지 않았다. 실제 견적 v3의 공통 서버 계약이 준비되면 그 계약으로 연결해야 한다.

최신 공개 master `939a1bec1485ac3c85434364de79e681bfdaac26` (#593)을 재확인했다. `sql/quote-v3-step1-20261011.sql`에는 요청/기준 테이블 등이 있으며 조회·저장 RPC 정의는 없다. `quote-calc.js`와 `quote-amounts.js`는 클라이언트 계산/읽기 모듈이다. 이를 모바일 전용 서버 계약으로 대체 사용하지 않았다. 운영 DB 설치 여부는 확인하지 않았다.
