# [단계 7 후속] 견적 날짜 선택과 페이지별 선택 보존

## 한 일

K1의 기존 ‘날짜 고르기’에 승인된 Claude source43의 ‘⑦ 아래 시트’를 연결했다. K1·K4에서 한 쪽의 선택을 바꿀 때 다른 쪽의 선택이 사라지던 문제도 보완했다. 현재 결과는 **로컬 합성 검토 구현**이며 운영 배포, 서버 저장, 고객 약속 확정이 아니다.

견적 화면은 source44, 날짜 선택 요소는 source43을 따른다. 날짜 시트의 배경막·손잡이·4열 선택지·검정 선택 상태·직접 입력 링크는 원본에서 가져왔다. 별도 확인 버튼을 추가하지 않았다. 제목에는 K1 원본의 ‘고객에게 약속한 날’을 연결했다. 기존 D 상담 입력과 날짜 선택 경로는 유지한다.

## 날짜 처리

- ‘날짜 고르기’를 열기만 하면 초안과 임시 보관 원문은 바뀌지 않는다.
- 내일·3일 후·7일 후는 공통 `ContactEntry.addDays`와 한국시간 오늘을 사용한 선택 후보다. 기존 명시 날짜도 함께 표시하며 같은 날짜는 한 번만 표시한다.
- 표시된 날짜를 누르면 해당 날짜를 로컬 견적 초안에 반영하고 시트를 닫는다. 직접 입력은 기기의 날짜 선택을 사용하며 유효한 날짜의 변경 사건에서만 같은 반영 경로를 호출한다.
- 유효하지 않은 윤일·존재하지 않는 날짜는 반영하지 않는다. 배경막·Escape로 닫으면 이전 날짜와 원문을 유지한다. 뒤로가기의 시트 닫기는 컨트롤러 검사로 확인했다.
- 날짜는 `draft.customer_due`와 선택 요소 ID인 `draft.datePreset`에만 보관한다. 표시 상태는 `unconfirmed-local-draft`다. 고객과 합의했다거나 견적 요청이 접수됐다고 판단하지 않는다.
- 보관 실패 시 현재 선택과 이전 보관 원문을 유지한다. 다시 보관한 뒤 같은 계정·세션·영업건·버전으로 재진입하면 복구된다. 계정이 바뀐 열린 시트에서는 반영을 거절한다.

## 페이지별 선택 처리

K1 공종과 K4 안 선택은 현재 보이는 20건만을 기준으로 초기화하지 않는다. 전체 조회 모델의 선택 ID를 유지하며 사용자가 누른 항목만 바꾼다. 25개 예시에서 1쪽 항목을 해제해도 2쪽의 5개 선택은 남으며, 양쪽에서 해제한 항목과 명시적인 ‘모두 해제’도 재진입·새로고침 후 유지된다. 별도 고객 선택 결과나 금액 합산을 생성하지 않는다.

## 바뀐 파일

- `mobile-approved-date-source.js`: source43 날짜 요소 원문·출처·선택 색.
- `mobile-approved-date.js`: 원본 노드에 날짜 후보와 직접 입력 동작 연결.
- `mobile-approved-quote.js`: K1 원본 날짜 요소에서 원본 날짜 시트 열기.
- `mobile-quote-flow.js`: 시트 열기·닫기·검증·로컬 반영, 중복 날짜 방지, 페이지 전체 선택 보존.
- `mobile-quote-review-model.js`: 명시 날짜의 표시·미확정 상태와 전체 선택 ID 제공.
- `mobile-guide-shell.js`, `mobile-approved-boot.js`, `mobile.html`: 기존 이벤트·필수 모듈·캐시 식별자 연결.
- `review-preview/fixture.js`, `stage7-fixture-models.json`: 합성 예시의 명시 날짜와 ‘날짜 고르기’ 동작 구분.
- 아래 집중 검사·결과·캡처 및 단계 7·8 파일 해시 목록.

서버 표·필드·함수·권한은 추가하거나 변경하지 않았다. 날짜·공종·안 선택은 현재 승인된 합성 예시에서만 편집할 수 있다. 실제 견적 생성·수정본 저장·금액 계산·발송 연결은 기존 서버 계약 확인 범위로 남아 있다.

## 남은 범위

공통 견적 서버 연결·실제 저장·발송은 이번 작업에 포함하지 않았다. 날짜를 선택했더라도 기존 방문·견적 일정이나 고객 약속을 덮어쓰지 않는다. 7단계 전체 완료 또는 운영 반영으로 보고하지 않는다. 기존 서버 미연결 사항은 [Claude 서버 계약 인수인계서](CLAUDE_QUOTE_MOBILE_SERVER_CONTRACT_20261011.md)를 따른다. 이 보고서 작성과 해시 갱신은 공개 업로드·병합·배포 완료를 뜻하지 않는다.
