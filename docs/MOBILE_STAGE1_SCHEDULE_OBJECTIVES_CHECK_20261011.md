# 1단계 — 복합 요청과 기존 일정 보존의 교차 검증

## 1. 완료한 작업

Draft #550의 후속 업무 생성 계약과 일정 보존 후보 SQL을 같은 로컬 DB에 설치해 검증했다. 고객과 합의한 견적·방문 날짜를 #550이 저장해도 일정 조회에서는 `unconfirmed`로 보이고, 내부 일정 변경으로 날짜를 바꿀 수 있는 문제를 재현했다. 수정 전 새 검사 9개 중 3개가 실패했다.

일정 조회·변경이 두 경로의 저장 근거를 함께 읽도록 보완했다. 고객 합의 업무는 재합의 근거를 처리하는 별도 계약이 생기기 전까지 일반 일정 변경으로 수정할 수 없다. 내부 계획은 같은 업무 ID로 날짜를 변경하고, 재시도해도 업무를 추가하지 않는다.

## 2. 바뀐 파일

- `sql/schedule-preserve-v1-20261011.sql`: 비공개 출처 확인 함수 추가, 기존 조회와 일정 변경 보호에 연결.
- `tests/request-schedule-integration.mjs`: 서로 다른 계약 사이의 보존·충돌·재시도·권한 검사 12개.
- `tests/work-request-contact-postgres.test.mjs`: 기존 #550 SQL 검사에 위 조합 검사 연결.
- `docs/SCHEDULE_PRESERVE_CONTRACT_20261011.md`: 고객 합의 출처 계약 보충.
- 이 보고서와 기존 통합 보고서: 구현·검증 범위 갱신.

## 3. 서버 칸·적용 SQL

새 공개 RPC, 테이블 열, 클라이언트 허용 목록은 추가하지 않았다. 기존 후보 SQL 내부에 `crm_security.schedule_v1_provenance(jsonb)`를 추가했다. 익명·로그인·서비스 역할의 직접 실행 권한은 없다. 기존 공개 RPC의 사용자·담당자·대상 접근 검사를 통과한 경로에서만 사용한다.

현재 표시 근거와 과거 고객 약속 보호를 분리한다.

- 현재 표시: 일정 이벤트의 날짜·수정시각·제목·담당·업무 종류를 대조한다. #550 이벤트는 같은 문의·업무 ID, 생성 성공 응답, 제목·담당·날짜·종류가 일치해야 출처로 인정한다.
- 변경 보호: 같은 업무에 고객 합의 이력이 있다면 제목이 바뀌어 현재 근거가 미확인으로 돌아가도 일반 일정 변경을 차단한다. 다른 업무의 합의 이력은 적용하지 않는다.
- #550 이벤트 테이블이 없는 DB에서도 기존 일정 기능이 작동하도록 선택적으로 조회한다. 없는 테이블을 미리 만들어 채우거나 원자료를 보정하지 않는다.

수정한 SQL은 아직 운영에 설치하지 않은 후보다. `CRM_SCHEDULE_V1`과 서버 설정은 계속 OFF다. #550 SQL/migration 원문을 이번 수정으로 변경하지 않았다.

## 4. 검증 결과

| 범위 | 결과 |
| --- | --- |
| #550 기존 검사 + 일정 보존 조합, 로컬 PGlite 실제 SQL | 75/75 통과 (기존 63 + 신규 12) |
| #550 없는 별도 DB의 일정 저장 계약 | 45/45 통과 |
| 같은 별도 DB의 문의 첫 응대 확인 계약 | 16/16 통과 |
| 누적 후보 JS/CJS/MJS 문법 | 42개 파일 통과 |
| 기준본 대비 누적 패치 적용 가능 검사 | 63개 파일 통과 |

확인한 내용: 고객 합의 날짜의 내부 변경 차단, 내부 일정 동일 ID 변경, 실패 시 원자료 유지, 양방향 변경 충돌 감지, 과거 응답 재시도의 날짜 되돌림 방지, 관리자 요청 완료 후 고객 업무 미완료 유지, 첫 응대 중복 확정 차단, 비공개 함수 권한.

모두 로컬 합성 DB 결과다. 실계정, 실제 운영 트리거, 여러 DB 연결의 동시 실행, 운영 설치·배포를 검증했다는 뜻이 아니다. UI는 변경하지 않았고 이번 서버 수정으로 화면 검사를 새로 수행하지 않았다.

## 5. PC·모바일 차이

PC·모바일이 공통 일정 RPC를 호출하면 같은 보호를 적용한다. 모바일 복합 요청 항목 입력·저장 경로는 아직 연결하지 않았다. 전체 흐름이 양쪽에서 완성됐다는 의미는 아니다.

## 6. 디자인 및 다음 단계

Claude의 화면·배치·스타일을 수정하거나 새 UI를 만들지 않았다. 복합 요청 항목 입력 위치의 기존 미결정 사항은 이전 인계서에 남아 있다. 이번 작업에서 추가 디자인 결정은 없다.

1단계 기능 검증을 계속하는 상태이며 다음 디자인 단계로 넘어가지 않았다. 운영 SQL 실행·고객 기록 수정·발송·GitHub 업로드·병합·배포는 모두 하지 않았다.
