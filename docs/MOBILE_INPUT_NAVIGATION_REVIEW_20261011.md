# 단계 8 후속 — 입력 보존과 화면 복귀

## 반영 범위

Claude 원본 I‑1~I‑3의 구성·색·간격·입력칸을 유지한 로컬 후보 수정이다. 원본 미리보기 8766과 운영 사이트는 변경하지 않았다. 확인한 master는 `ad209245d50bdc46569b9533fdcf3b601936f679`(#596)이다.

## 확인한 오류와 수정

| 동작 | 수정 전 | 로컬 후보 |
|---|---|---|
| C → 명함 입력 → 뒤로 → 재진입 | 일반 뒤로가기도 취소로 처리해 네 입력값 삭제 | 같은 계정·세션·영업건의 초안을 보관한 뒤 복귀 |
| 기기 보관 실패 후 뒤로 | 보관 실패를 무시하고 현재 입력 제거 | 현재 입력을 유지하며 이동 차단; 보관이 회복되면 다시 이동 가능 |
| 다른 핸들이 보관본 변경 | 삭제 충돌을 무시하고 현재 입력 제거 | 현재 입력과 다른 핸들의 보관본을 모두 유지; 자동 병합·덮어쓰기 없음 |
| 입력 중 보관 실패 | 모델에는 오류가 있지만 화면 설명은 그대로 | Claude 원본의 기존 설명문 갱신; 편집 요소·포커스 유지 |
| 계정·영업건 변경 후 뒤로 | 입력 경로만 남아 빈 화면 | 이전 입력 적용을 차단하고 현재 승인 화면으로 복귀 |
| 같은 영업건의 버전 변경 후 재진입 | 읽기만 해도 이전 초안 삭제 | 원문 보존, 자동 재연결 차단; 빈 입력 화면으로 덮지 않음 |
| 화면 이탈 중 보관 실패 | 늦은 조회 시작 또는 음성 문장 표시 누락 가능 | 음성·사진 인식·조회 자원을 종료하고 현재 텍스트 유지; 문서가 복원되면 승인 화면에 다시 표시 |
| 처음 열 때 보관소 읽기 실패 | 실패한 보관 핸들로 빈 입력 화면을 열어 복귀·재시도 차단 | 기존 C 상세 또는 D 상담 입력 유지; 다시 누르면 보관소를 새로 조회 |
| 보관된 초안 손상 | 복원에 실패해도 빈 입력 화면 표시 | 손상 원문을 지우거나 덮지 않고 기존 화면 유지 |
| 입력 없이 명함 화면에서 뒤로 | 빈 초안을 쓰다가 저장 공간 부족 시 복귀 차단 | 입력하지 않은 경우 저장 없이 복귀; 수정·인식한 초안은 기존 보존 검사 적용 |

말하기의 명시적 취소는 검토 초안만 지운다. 기존 D의 연락 결과·상담 내용·다음 업무·요청 선택을 유지한다. 검토 내용을 D에 반영하는 것은 서버 응대 저장과 다르다.

## 바뀐 파일

- `mobile-input-flow.js`: 일반 복귀와 명시적 취소 분리, 보관 실패 시 현재 상태 유지, 계정·대상 변경 정리, 페이지 이탈·복원 수명 관리. 최초 읽기 실패 시 진입 취소·핸들 해제, 무입력 I3 복귀 시 불필요한 저장 생략.
- `mobile-input-draft.js`: 버전 불일치 초안 보존, 오래된 핸들 삭제 차단, 삭제 실패 후 재시도. 최초 읽기에 성공한 경우에만 핸들 등록.
- `mobile-guide-shell.js`: 실패한 복귀·이동 중단, 기존 설명문 갱신, 기존 목록 위치 유지.
- `mobile.html`: 위 모듈의 캐시 식별자 변경만.
- 해당 회귀 검사·검사 결과·이 문서·단계 manifest.

## 추가·바꾼 데이터 필드

없음. 기존 탭 범위 `sessionStorage`의 미전송 초안만 사용하며 서버 표·RPC·권한·연락처·활동·업무·요청·집계는 변경하지 않았다.

## 점검과 한계

검사 결과는 [뒤로가기 검사 7개](../review-preview/stage8-back-browser-verification.json), [페이지 이탈·복원 검사 5개](../review-preview/stage8-pagehide-browser-verification.json), [초안 모듈 검사 13개](../review-preview/mobile-input-draft-verification.json), [새로고침 검사 8개](../review-preview/stage8-recovery-browser-verification.json)에 기록한다. 실제 버튼 조작에는 합성 예시를 사용하고 외부 요청과 CRM 쓰기를 차단했다. 원본 DOM·스타일 대조 8개, 연락처 조회 컨트롤러 18개, OCR 컨트롤러 16개, 실제 입력 진입 4개도 통과했다.

후속으로 [초기 실패·재진입 검사 5개](../review-preview/stage8-open-retry-browser-verification.json)를 추가하고 뒤로가기 7개를 다시 통과했다. 최초 핸들 생성 실패·생성 후 읽기 실패·손상 원문 보존·기존 D 입력 유지·무입력 I3 저장 공간 부족을 확인한다. 연락처 조회 검사 18개와 초안 모듈 13개도 통과했다. 시험용 캐시의 빈 읽기 응답을 실제 API와 같은 `{ok:true,value:null}`로 맞췄다.

![일반 뒤로가기 후 네 입력값이 복원된 합성 I3 화면](../review-preview/approved-i3-draft-recovery.png)

보관 기간은 마지막 성공한 보관부터 30분이다. 계정·세션 변경 시 정리 정책은 유지한다. 영업건 정보가 바뀐 초안을 현재 영업건에 자동 적용하지 않으며, 이 초안을 비교·선택하는 새 UI는 만들지 않았다. 보관 실패 후 탭 자체가 파기되면 메모리만으로 입력을 복구할 수 없으므로 앱·브라우저 종료 후 보존을 보장하지 않는다.

실제 마이크·OCR·iOS Safari·Android Chrome 실기기와 운영 저장 대사는 미검증이다. 이번 결과를 운영 반영이나 단계 8 전체 완료로 표시하지 않는다.

## PC와 다른 점 / 미결정 사항

PC와 다른 업무 판단·서버 저장은 추가하지 않았다. I‑3 연락처 저장은 계속 비활성이다. 회사의 귀속 기준과 명시적인 기존 사람 선택·현장 연결 계약은 미확정이며 이번 수정에서 결정하지 않았다. 새 디자인 결정은 없다.
