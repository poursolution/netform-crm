# [단계 5] 기록·등록(E), 일정(F), 오늘 마감(H), 유사 현장(J-4)

상태: **로컬 검토용 부분 구현**. 운영 배포·운영 데이터 저장 없음. 이전 단계의 A/B/C/D 및 전송 대기 경로를 유지한다.

## 적용한 원본과 범위

- 사용자가 직접 지정한 8766 미리보기의 `guide42-screens.json` E/F/H/J-4 원본 노드·인라인 스타일을 사용했다. 새 배치·카드·입력 칸을 만들지 않았다.
- source43 가이드의 기능 정정은 적용한다. 예시의 날짜·요일을 운영 값으로 고정하지 않고 KST 날짜로 계산하며, 지난 일정은 미수행으로 확정하지 않는다.
- 폰 틀과 글꼴·색·여백은 원본을 유지한다. 스크롤, 키보드 조작, 실제 입력 요소와 데이터 연결만 추가했다.
- 합성 데이터는 탭 제목에 예시/운영 아님을 표시한다. 원본 H의 5·1·4 등은 원본 모양을 보는 예시이며 실제 업무 집계가 아니다.

## 연결한 동작

### E / J-4

- 기존 현장 활동 → B의 담당 범위 검색 → 선택한 영업건의 D 연락 결과 입력. 기존 다음 업무는 유지하며 진입만으로 저장하거나 완료하지 않는다.
- 현장명 입력 → 유사 현장 후보 → 명시적 선택. 후보는 현재 계정의 `myDeals()`에서 이름·주소를 찾아 유효한 현장 UUID로만 묶는다. 같은 이름의 다른 현장을 합치지 않는다.
- 현장 ID 미연결 건은 별도로 계산한다. 현재 불러온 내 영업건 범위이며 회사 전체 중복 검사를 완료했다는 의미가 아니다.
- 검색어·선택 현장 ID는 계정별 sessionStorage에 30분간 보존한다. 읽기 복원·저장 후 재확인·계정 변경 검증을 하며, 로그아웃 사건에서 해당 임시 기록과 메모리 선택을 지운다.
- 새 영업건 생성·병합·담당자 알림은 실행하지 않는다. 등록 후반 화면과 서버 저장 성공 확인 경로가 아직 연결되지 않았기 때문이다.
- 사진·자료 업로드와 독립 일정 등록은 원본 진입만 유지하며, 미연결 이유를 기존 알림으로 안내한다. 예전 입력 창을 열지 않는다.

### F

- 현재 담당자의 공통 업무 투영값 `openNextActions`를 우선 사용하고, 없을 때만 기존 다음 업무 값을 읽는다. 동일 업무 ID는 중복 표시하지 않는다.
- 명시된 관리자 요청 기한은 내부 기한으로 표시한다. 날짜만 있는 업무에서 약속 시간을 추정하지 않는다.
- 월~일과 선택 날짜는 KST 기준 실제 날짜로 맞춘다. 날짜 선택·현장 상세·뒤로 가기에서 선택 날짜를 유지한다.
- 기한이 지난 열린 업무는 결과 확인 대상으로 표시한다. 완료 상태와 완료 시각이 함께 확인돼야 완료로 표시한다.
- 20건을 넘는 목록은 공용 ListPager의 쪽 번호를 사용한다.
- 주간 연락·다음 업무 등록·약속 준수의 공통 측정값은 아직 연결하지 않았다. 원본 세 칸에는 확인 필요를 표시하며 0%나 임의 성과 수치를 만들지 않는다.
- 전체 과거 일정 원장, 문의 일정, 실계정 조회 범위 대사는 이번 구현 완료 범위가 아니다.

### H

- 원본 세 카드와 마감 버튼을 표시한다. 실제 완료 업무 수·미완료 약속 수·내일 업무 수의 공통 확정 집계는 미연결이다.
- PC의 연락 활동 수와 확정 업무 완료 수가 다르므로 기존 활동 합계를 완료 수로 대체하지 않았다.
- 미완료 사유·내부 다음 처리일·고객 재합의 입력이 원본 H에 없고 서버 마감/공유 성공 응답도 확인되지 않아, `마감하고 공유`는 실행 불가다.
- PC의 클립보드 복사를 서버 저장 또는 공유 전달 완료로 취급하지 않는다.
- 가이드 글에는 A 맨 아래 오늘 마감 버튼이 명시되어 있으나, 사용자가 지정한 A 원본 그림에는 그 버튼 노드가 없다. 새 모양을 정하지 않고 현재는 아래 검토 주소로만 H를 확인한다. 그림 보완 후 가이드에 정한 위치로 연결해야 한다.

## 추가·바꾼 데이터 필드

서버 표·SQL·PC 데이터 필드·권한 변경 없음.

로컬 임시 입력만 `crm:mobile-registration:v1:<계정>`에 `v, actor, at, expiresAt, query, selectedId`를 보존한다. 새 현장이나 영업건 저장 완료를 의미하지 않는다. 일정 모델은 기존 읽기 값의 투영이며 서버에 새 상태를 쓰지 않는다.

## 점검표 통과 / 미통과

통과:

- E/J-4/H 원본 인라인 스타일·예시 텍스트 대조.
- E→B→D, E→J-4→E, F→C→F 및 A/B/E/F 탭 이동.
- 입력 복원, 계정 분리, 로그아웃 정리, 같은 이름 자동 병합 방지.
- 같은 이름의 현장은 주소로 구분, 마지막 페이지 한 건도 직접 선택 필요.
- 임시 보관 실패 표시, 신원 초기화 없이 계정만 바뀐 경우 이전 입력 저장 차단.
- 한글 조합 중 입력칸 유지(합성 IME 사건 검사, 실기기 미검증).
- KST 날짜·요일, 지난 업무 미완료 추정 방지, 공통 20건 쪽 번호.
- 320/375/480px 가로 넘침 없음, 원본 글자 크기 유지.
- 원본 화면 스크립트 실패 시 기존 UI 노출 차단.
- 마감/공유 미연결 상태에서 저장·복사·외부 이동 없음.
- A/B/C/D·전송 대기·부분 실패 재시도의 기존 집중 검사 유지.

미통과 / 미검증:

- E 새 현장 등록 전체, 사진 업로드, 독립 일정 등록: 후속 원본 화면 및 안전한 저장 연결 미완성.
- H 마감 저장·공유 전달, 실제 집계: 입력 원본과 공통 계약 미연결.
- F의 세 주간 지표: 공통 측정값 미연결.
- 실계정 PC/모바일 동일 결과 대사, iOS Safari·Android Chrome 실기기 사용 테스트 미실시.
- F의 긴 처리 확인 안내에서는 오른쪽 확인이 두 줄로 줄바꿈된다. 원본 칸 폭은 유지했다. 줄바꿈 허용 여부와 긴 안내 문구 기준은 Claude 검토 항목이다.
- 운영 배포 없음. 로컬 합성 검사는 실계정 저장 검증을 대신하지 않는다.

검사 근거는 `review-preview/stage5-browser-verification.json`, `stage5-regression-verification.json`, `approved-ej-verification.json`, `approved-h-verification.json` 및 `registration-safety-verification.json`과 일정/등록 테스트 결과에 있다.

최종 집중 검사: 브라우저 흐름 10개, 등록 안전성 4개, 등록 컨텍스트 12개, 일정 모델 16개 통과. 기존 회귀 검사 파일 12개도 통과했으며 E/J-4 원본 대조는 안전성 수정 후 다시 통과했다.

## PC와 다른 점

- 완료/마감의 의미를 모바일에서 새로 정하지 않았다. 같은 서버 계약이 확인되지 않은 실행은 연결하지 않았다.
- PC의 기존 등록은 로컬 목록 변경 후 저장 확인 전 성공 표시가 가능한 경로가 있어 그대로 재사용하지 않았다.
- 모바일의 F는 현재 불러온 내 업무만 다룬다. PC의 전체 일정·보고서와 같은 범위라고 표시하지 않는다.

## Claude 인수인계: 원본이 더 필요한 부분

새 배치를 Codex가 정하지 않는다. 아래 디자인 공백과 데이터 계약을 먼저 연결해야 단계 5를 완료할 수 있다.

| 부분 | 필요한 원본 / 결정 | 필요한 데이터·저장 계약 |
|---|---|---|
| E/J-4 등록 2~4단계 | 선택 현장에 새 영업건 추가 및 새 현장 등록의 다음 화면, 돌아왔을 때 입력 보존 | PC 필수값·생성 권한·선택한 site_id·client_ref를 보존하고 서버 성공 후 생성 ID 반환 |
| E 사진·자료 | 현장 선택 뒤 업로드·부분 실패·재시도 화면 | 현장/영업건 연결, 업로드 성공 확인, 동일 파일 중복 방지 |
| E 일정 등록 | 업무 종류·기존 업무 선택·날짜 변경과 새 추가를 나누는 원본 | 공통 일정 저장 계약·고객 약속/내부 계획·기존 ID 유지 |
| H 오늘 마감 | 가이드 A 맨 아래 오늘 마감 버튼의 그림 보완, 미완료 사유·내부 다음 처리일·고객 재합의 입력 원본 | 확정 업무 원장 집계, 마감 저장 ID, 공유 전달 상태. 저장과 전달 성공을 별도 확인 |

기존 고객 약속일을 내부 재처리일로 덮어쓰지 않는다. H 버튼을 눌렀다는 사실만으로 업무나 요청을 일괄 완료하지 않는다.
