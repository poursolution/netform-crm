# 영업건 재배정 시 미완료 업무 승계 — 2026-10-10

대상: 영업운영 CRM `poursolution/netform-crm`. 기준 master: `948fd3cadcdc5b67068f48b954f9f94319944ad3`.

## 확인한 문제

기존 `crm_deal_reassign_handover_v1`은 영업건 담당자와 인계 요청을 변경하지만, `next_actions`의 기존 담당자를 변경하지 않았다. 합성 데이터에서 견적 발송·방문 업무 2건이 이전 담당자에게 남는 실패를 먼저 재현했다. 실제 고객을 재배정해 테스트하지 않았다.

## 수정 범위

- 같은 영업건의 `status='open'` 업무 중, 이전 `owner_id`에 해당하는 사용자와 담당자 이름이 일치하고 그 이름이 유일한 경우에만 새 담당자에게 승계한다. 비활성 이전 담당자도 식별할 수 있지만 동명이인은 자동 추정하지 않는다.
- 완료·취소 업무, 다른 담당자의 별도 업무, 담당 미지정 업무, 다른 대상의 업무는 보존한다. 업무 ID·내용·기한·완료 상태·근거 활동·생성 시각은 변경하지 않는다.
- 재배정·업무 승계·인계 요청·변경 활동·재시도 영수증을 하나의 트랜잭션으로 저장한다. 후속 승인 요청이 실패하면 모두 되돌린다. 이전 요청의 재시도는 최초 응답만 반환해 이후 재배정을 되돌리지 않는다.
- 응답과 담당 변경 활동에 `transferred_next_actions: [{id, from, to}]`를 추가한다. 새 테이블·칼럼·RPC·권한 확대는 없다.
- `deal-owner.js`는 서버 확인 후 일치하는 업무 ID와 이전 담당자의 로컬 열린 업무만 갱신한다. ID 없는 초안·완료된 업무·독립 담당 업무는 추정 갱신하지 않는다. 구버전 서버에 이 응답이 없으면 업무를 바꾸지 않는다.

## 적용과 검증

1. 검토한 `sql/deal-reassign-handover-20261007.sql`을 운영 승인 후 재적용한다. 반복 적용 가능한 기존 함수 교체이며, 설치 자체로 과거 업무를 일괄 재배정하지 않는다.
2. 기존 `pc-manager-transport.js` 허용 목록, `pc-error-state.js` 오류명, `deal-owner.js`의 `CRMRelease.has(RPC.change)` 게이트는 유지한다. 새 RPC 추가가 아니므로 허용 범위를 넓히지 않는다.
3. SQL 설치 확인 후 클라이언트 PR을 병합·배포한다. 운영 고객 재배정·실제 알림 발송 없이 함수 정의와 배포 산출물을 확인한다.

로컬 검증: `work-request-handover-postgres.test.mjs`, `work-request-handover.test.cjs`, `deal-owner-postgres.test.mjs`, `approval-apply-postgres.test.mjs`, `release-contract.test.cjs`. 승계 대상 선별, 기한·내용 보존, 권한 차단, 동명이인·owner_id 없는 이관 자료 제외, 전체 롤백, 늦은 재시도를 포함한다.

## 한계

이번 변경은 앞으로 기존 재배정 RPC로 저장하는 영업건에 적용한다. 이전에 담당자가 어긋난 업무의 일괄 정리, 문의 재배정, 약속별 독립 업무 생성, 기존 메모에서 약속 추출은 별도 범위다. 로컬 임시 업무가 아직 서버 업무 ID를 받지 못한 경우도 자동 승계하지 않는다. 디자인·표시 위치·HTML 구조·CSS는 수정하지 않는다.
