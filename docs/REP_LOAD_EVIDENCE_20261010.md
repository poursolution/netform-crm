# 담당자 업무량 — 기록 보완 집계와 근거 연결

기준: master d4e1a77501b25f50263c52ca96cede5fbd27ac7f. 기능 수정이며 디자인·서버 SQL·운영 원자료 변경 없음.

## 확인한 문제와 수정

- `ExecWording.loadOf`는 다음 행동이 없으면 이미 `기록 보완 먼저`로 판단하지만 `counts.fix`에는 해당 영업건이 빠져 있었다.
- 기존 `specLoad` 근거 목록도 다음 행동 누락을 빠뜨렸다. 영업사원 관리의 숫자는 별도로 `L.miss.length`를 사용해 문의 이관 기록 확인 대상까지 빠졌다.
- 이제 단계 근거 누락(`miss`) ∪ 다음 행동·날짜 누락(`noNext`) ∪ 문의 이관 기록 확인(`review`)을 하나의 `fixes` 목록으로 만든다. 영업건과 문의는 별도 ID 공간이며 같은 영업건에 사유가 여러 개여도 한 건만 센다.
- 업무량 표의 기존 숫자, 근거 창의 기존 숫자와 목록이 같은 집합을 사용한다. 여러 보완 사유는 기존 근거 칸에 함께 전달한다.
- 배정 추천 순서·잠정 문턱 6/20·정체 계산·전체 대상 선정·쓰기 동작은 그대로다. 업무를 자동 생성하거나 담당자를 바꾸지 않는다.

## 검증

- 합성 영업건 17건의 다음 행동 누락이 수정 전 0건으로 집계됨을 재현했다.
- 수정 후 17건 집계 = 근거 목록 17건. 동일 영업건의 여러 사유는 한 건, 같은 ID 문자열의 문의와 영업건은 별도 두 건으로 보존한다.
- 완료된 입력이 있는 건은 추가 보완 대상이 되지 않고 첫 연락 우선 판단도 유지한다.
- 기존 영업사원 관리 HTML의 숫자 바인딩을 실행해 공통 집계값이 출력되는지 확인한다.
- `tests/rep-load-evidence.test.cjs`를 필수 CI에 추가했다.

## Claude 후속 확인 — 화면은 Codex가 변경하지 않음

- `reps-b.js loadHtml()`의 하단 설명은 아직 기존 문턱(첫 연락 → 오늘 처리 6건 → 기록 보완 20건 → 가능)만 요약한다. 실제 판단에는 다음 행동 누락·정체·관계 분류 미확인도 포함되므로 기존 설명을 어떻게 정리할지 Claude가 결정한다.
- 정체는 현재 `r.stale`라는 집계 숫자만 받는다. 이 변경에서 현장별 정체 사유를 추정해 보완 목록에 넣지 않는다. 관계관리 자료 자체가 미조회인 경우도 가짜 현장 목록을 만들지 않는다. 별도 안내가 필요하면 기존 자리와 표시 방식을 Claude가 결정한다.
- 새 카드·버튼·표·칸·스타일은 추가하지 않는다. 기존 `왜 이 판단인지` 창과 페이지 넘김을 유지한다.
