# 잔디 응대 페이지 → CRM 연락 결과 · 견적 발송 · 영업건 전환 (2026-11-09)

## 결론
- 담당자가 잔디 알림 링크(n8n 응대 페이지)에 적으면 **CRM 첫 시도 · 첫 연결 · 견적 발송 · 파이프라인 '컨설팅 설계' 영업건**까지 이어지게 한다.
- CRM 받는 쪽: `supabase/migrations/20261109120000_inquiry_external_response_contact_quote.sql` (이 PR). **운영 반영은 대표님 승인 뒤.**
- n8n 쪽: 「견적문의 담당자 배정」(`rXU5jbSUlNRz11KN`) 칸 3개 수정. **CRM 반영 뒤 보람님 확인을 받고** 편집기에서 고친다.
- 순서: CRM 먼저 → n8n. (n8n 을 먼저 바꿔도 CRM 이 새 칸을 무시할 뿐 깨지지 않지만, 그 사이 기록은 CRM 으로 안 넘어간다.)

## 변경 전 → 변경 후

| | 변경 전 | 변경 후 |
|---|---|---|
| 응대 페이지 | 진행상태 · 다음 챙길 날 · 응대내용 | + **연락 결과**(필수: 연결됨 · 회신 받음 · 부재 · 번호 오류 · 문자) + **견적서 보낸 날 · 금액(만원)**(진행 중 상태일 때만, 선택) |
| CRM 견적문의 | 상태 · 응대내용만 바뀜 | + 연락 결과 기록 1줄, **첫 시도 · 첫 연결 시각**(처음 한 번만) |
| 견적 | 기록 없음 → 파이프라인 전환 0건 | 상태 '견적서 발송완료' · 견적 버전(금액 있을 때) · 보낸 날 + 7일 '고객 반응 확인' 할 일 · **'컨설팅 설계' 영업건 자동 생성** |
| 자동 전환이 막힐 때 | — | 응대 · 연락 결과 · 견적은 저장, 문의는 '전환 기준 충족'으로 남아 CRM 전환 대기에서 넘김. 이유는 이벤트 reason(`RESPONSE_SYNCED_CONVERSION_REVIEW`)에 남음 |

연락 결과 → CRM 값: 연결됨 → 연결됨(접촉) · 회신 받음 → 고객 회신(접촉) · 부재 → 부재(시도) · 번호 오류 → 번호오류(시도) · 문자 → 채널 '문자', 결과 '회신대기'(CRM 규칙상 시도 횟수 · 접촉 어디에도 안 셈).

## CRM 받는 쪽 규칙 (마이그레이션)
- n8n 이 이미 부르는 `crm_inquiry_change_enqueue_v1`(kind `response`) 본문에 `contact_result` · `quote_sent_on` · `quote_amount`(원) 를 더 받는다. 셋 다 없으면 지금과 똑같다.
- 받는 단계에서 검사: 모르는 연락 결과 · 미래/1년 넘은 날짜 · 종료 상태(배드핏 등)에서 견적 · 날짜 없는 금액 → 이벤트를 받지 않고 오류.
- 기록의 주인 = 그 문의 담당자. 담당이 없거나 CRM 로그인이 없으면 연락 결과 · 견적은 건너뛰고 `RESPONSE_SYNCED_FLOW_REVIEW`.
- 영업건 생성은 CRM 전환 명령과 같은 기준(담당이 승인된 본사 영업 · 현장 이름이 하나로 맞을 때). 막히면 위 '전환 대기'.
- 운영 함수 두 곳(enqueue · apply)은 **본문을 읽어 정해진 한 줄씩만** 덧붙인다. 자리가 정확히 한 곳이 아니거나 필요한 표 · 칸(`inquiry_contact_logs.contact_result` 등)이 없으면 아무것도 바꾸지 않고 멈춘다.
- 시험: `node --test tests/inquiry-external-response-contact-quote.test.cjs` (PGlite, 6개). 10/4 운영 반영본 큐 SQL 사본(`tests/fixtures/inquiry-change-events-v1.deployed-20261004.sql`) 위에서 돌린다.
- 되돌리기: 두 함수 본문에서 `inquiry_external_flow_v1` 표시가 붙은 줄을 빼고 다시 만든다.

## n8n 변경안 (편집기에서, 고치기 전 버전을 먼저 내려받아 둔다)
아래는 10/5 · 11/6 사본 기준이다. 운영 칸이 그 뒤 바뀌었으면 같은 자리를 찾아 넣는다.

1. **응대내용 UI** (Respond to Webhook 본문)
   - `<div id="statusDesc" …></div>` 바로 뒤에 '연락 결과' 고르기(`name="contactResult"`, 필수)와 '견적서 보낸 날'(`quoteSentOn`, date) · '견적 금액'(`quoteAmountMan`, 만원) 묶음(`id="grp-quote"`, 진행 중 상태일 때만 보임)을 넣는다.
   - 스크립트: 진행상태가 전화응대 완료 · 현장방문예정 · 견적서 발송예정 · 보류면 견적 묶음을 보이고, 연락두절이면 연락 결과 기본값 '부재'. 보낸 날은 오늘까지만. 협약문의 화면에서는 연락 결과를 숨긴다. 금액만 넣고 날짜가 없으면 저장을 막는다.
   - 본문 안 글자에는 작은따옴표를 쓰지 않는다(n8n 식 안 문자열이 깨짐).
2. **응대 데이터 추출** (Code) — `const now = new Date();` 앞에 새 칸 읽기 · 검사, 반환 값에 `contactResult` · `quoteSentOn` · `quoteAmount`(원) 추가.
3. **Supabase 최초응대 동기화** (HTTP · p_event) — 끝의
   `next_action_date: d.nextDate || null };` 를
   `next_action_date: d.nextDate || null, contact_result: d.contactResult || null, quote_sent_on: d.quoteSentOn || null, quote_amount: d.quoteAmount ?? null };` 로.
4. (선택) **응대 구글시트 업데이트** — 보낸 날이 있으면 시트 진행상태도 '견적서 발송완료'로(CRM과 같게, 새벽 대조에서 차이로 안 뜨게). **잔디 응대내용 알림** 글에 '연락 결과' 한 줄 추가.

붙여 넣을 전체 본문(응대내용 UI · 응대 데이터 추출)은 웹훅 주소가 들어 있어 저장소에 넣지 않고 세션 공유 메모 폴더에 둔다.

## 시험 방법 (시험 문의 1건 · 고객 아님)
조건: CRM 마이그레이션 운영 반영 뒤(대표님 승인), n8n 수정 뒤(보람님 확인). 잔디로 글이 나가므로 보람님 확인을 받고 한다.
1. 시험 문의 1건: 현장명 `[연동 테스트·고객 아님]`, 연락처는 실제 고객이 아닌 번호, 브랜드 1곳, 담당은 시험에 동의한 **승인된 본사 영업 1명**(영업건 생성 기준). 시트 행 + CRM 견적문의가 함께 있어야 한다.
   - 주의: 「응대 기록 없음 반복 알림」(`5dczyYypN5gBPUZs`, 평일 09:00 · 13:30)이 응대내용 빈 시험 행을 잡아 잔디로 보낼 수 있다 → **13:50 이후 만들고 바로 1차 저장**하거나, 끝까지 그날 안에 정리한다. 반복 알림 흐름은 건드리지 않는다.
2. 응대 링크로 열어 ① 진행상태 '전화응대 완료' · 연락 결과 '부재' · 내용 '시험' 저장 → CRM 견적문의 상세: 연락 결과 1줄(부재), 첫 시도 시각 = 저장 시각, 첫 연결 비어 있음.
3. ② '견적서 발송예정' · 연락 결과 '연결됨' · 보낸 날 오늘 · 금액 100 저장 → CRM: 상태 '견적서 발송완료', 첫 연결 시각, 견적 v1 100만원, 할 일 '고객 반응 확인'(+7일), 파이프라인 '컨설팅 설계'에 시험 영업건(예상금액 100만원).
4. ③ 같은 링크로 한 번 더 저장 → CRM은 바꾸지 않고 '전환된 문의'로 검토(정상). 전환 뒤 기록은 영업건에서 한다.
5. n8n 실행 기록에서 세 번 모두 성공, CRM 문의 이력에 `source: n8n` 표시 확인.
6. 정리: CRM 시험 영업건 · 문의 휴지통, 시트 행 삭제, 잔디 시험 글 삭제. 되돌릴 땐 n8n 은 내려받아 둔 버전으로, CRM 은 위 '되돌리기'.

## 남는 것
- 전환 뒤에도 담당자가 같은 응대 링크에 적으면 CRM 에는 '검토'로만 남는다(영업건으로 안 이어짐). 다음 단계 후보: 전환된 문의의 응대 저장을 영업건 활동으로 넘기기.
- 첫 시도 · 첫 연결 시각 = 응대 페이지 **저장 시각**(통화 시각을 따로 받지 않음).
- 기존 '다음 챙길 날' 입력칸 아래 안내 글이 칸과 겹쳐 보인다(원래 있던 화면 문제, 이번 변경과 별개).
- 과거 43건은 소급하지 않는다.
