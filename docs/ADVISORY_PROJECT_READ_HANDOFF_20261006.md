# 기술자문 기본 정보 조회 연결 — 2026-10-06

상태: 서버 조회 SQL 및 로컬 PostgreSQL 검증 준비. 운영 설치 및 화면 연결 전이다.

기존 계약 문서 조회는 검증된 문서 연결이 있어야 반환하므로, 원본 기본 정보가 수신돼도 문서 없는 프로젝트는 표시할 수 없다. 새 조회는 기본 정보 저장소를 읽으며 계약 문서를 생성하지 않는다.

## 호출 계약

- `crm_advisory_project_read_v1(p_after text = null, p_deal_id uuid = null)`
- 응답: `{ok: true, items: [...], next_cursor: string | null}`. 원본 프로젝트 ID 순서로 최대 20건을 반환한다.
- 첫 호출은 `p_after: null`, 다음 쪽은 이전 응답의 `next_cursor`를 사용한다. 필터나 영업건이 바뀌면 첫 쪽부터 읽는다. 쪽 번호 표시는 기존 `ListPager`를 사용한다.
- `p_deal_id`를 지정하면 해당 영업건을 읽을 수 있는지 먼저 검사한 뒤, 명시적으로 연결된 원본 프로젝트만 반환한다. 같은 현장명이나 담당자 이름을 연결 키로 사용하지 않는다.
- 승인된 관리자는 전체 기본 정보를 조회한다. 그 외 계정은 기존 영업건 조회 권한 또는 유효한 기술자문 원본 열람 권한이 있는 프로젝트만 조회한다. 원본 담당자 이름으로 권한을 부여하지 않는다.
- 반환 필드는 원본 ID·revision 문자열·수신시각·현장·공사·업체·현재 원본 담당·원본 상태·원본 계약 문서 유형·문서 표시 계약일·원본 기술자문 계약금액·공사 진행 사실이다. 원문 payload, 문서 URL, 계약 본문은 반환하지 않는다.

## 화면 연결 시 지켜야 할 기준

문서 없는 원본 정보의 표시 위치는 사용자/Claude 확인 대기다. 이번 변경은 HTML·CSS·화면 JavaScript를 수정하지 않는다. 기존 계약 조회 RPC는 그대로 유지한다.

원본 기술자문 금액·문서 표시 날짜·현재 담당자는 아파트 공사 계약실적의 금액·체결일·당시 실적 귀속을 대신할 수 없다. 기본 정보 조회만으로 계약실적을 합산하거나 영업건을 자동 생성·복원하지 않는다. 값이 없는 금액은 0원으로 표시하지 않는다.
