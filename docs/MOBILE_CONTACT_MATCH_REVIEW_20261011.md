# [단계 8 후속] 명함의 기존 연락처 후보 조회

상태: **로컬 후보 구현·합성 검사 완료, 운영 미적용**. Claude I-3 원본의 기존 안내 줄에서 번호 수정·조회 중·실패·권한 범위 내 후보 수를 갱신한다. 연락처 저장, 사람 병합, 현장 연결, 회사 귀속은 실행하지 않는다.

## 한 일

- 번호를 수정해도 이전 중복 경고가 남던 오류를 수정했다. 기존 안내 span만 갱신해 입력 중 포커스·커서·직접 수정값을 유지한다.
- 실사용 경로는 일부 로딩된 `myDeals().contacts`로 전체 중복 여부를 단정하지 않는다. 공통 서버 조회의 확인된 결과만 후보로 사용한다. 합성 예시는 운영 조회 없이 예시 자료만 사용하며 이를 표시한다.
- 사람 수는 연락처 UUID, 연결 수는 영업건 UUID로 구분한다. 같은 번호의 서로 다른 사람은 합치지 않는다. UUID 없는 로컬 투영을 사람 수에 넣지 않는다.
- 입력 번호·계정·세션·영업건·버전·화면·재촬영이 바뀌면 진행 중 조회와 이전 결과를 폐기한다. 동일 정규화 번호의 표시 형식만 바뀌면 중복 조회하지 않는다.
- 후보 결과는 기기 초안에 저장하지 않는다. 복구 후 다시 조회하며, 실패·미설치·미조회는 0건으로 바꾸지 않는다.
- 재촬영 시 직접 고친 값이 유지된다는 사실을 기존 설명 줄에서 알린다. 자동 덮어쓰기나 새 입력 칸은 없다.

## 추가·바꾼 데이터 필드

새 테이블·고객 필드·저장 필드는 없다. 아래 RPC만 로컬로 준비했다.

`crm_contact_match_read_v1(p_opportunity_id uuid, p_phone text, p_page integer default 1)`

- 기준: 현재 `crm_security.actor()`와 `can_deal(id,false)`를 대상 영업건 및 모든 후보 연결에 적용한다. 읽기 권한을 쓰기 권한으로 확대하지 않는다.
- 전화번호: 010 11자리 또는 명시적 +82 표기를 정규화해 정확히 일치하는 번호만 조회한다. O→0 등 OCR 추측은 하지 않는다.
- 연결: `deals.contact_id` 또는 `contact_assignments.person_key → opportunity_id`. 이름·현장명·`current_site`로 연결하지 않는다. 과거 연결도 후보 근거이며 현재 근무·대표자·동일인 확정 증거가 아니다.
- 반환: 계약 표식 `contact-match-read-v1`, 조회 계정·대상·버전·정규화 번호·권한 범위, 페이지당 최대 20명, 권한 범위 내 고유 후보 수. 후보마다 contact UUID와 접근 가능한 영업건 연결 최대 20개를 반환한다. 권한 밖 후보·연결·개수, 회사·이메일·수신동의는 반환하지 않는다.
- 모든 후보는 `can_link:false`다. 단순 조회 결과를 저장 승인으로 쓰지 않는다. UI에는 현재 후보 수만 표시하며 새 선택 목록·쪽 번호·선택 조작은 만들지 않았다.
- 클라이언트는 정확한 계정·대상·버전·입력·페이지와 응답의 개수·고유 UUID를 검증한다. 15초 제한, UTF-8 512KiB 응답 상한, 각 텍스트 4096자 상한을 넘으면 실패로 처리한다. 자동 재시도·쓰기 큐·로컬 결과 캐시는 없다.

SQL은 읽기 전용 transaction에서도 실행하며 검사 전후 합성 행이 동일함을 확인했다. 권한 밖 후보·연결 추가 시 응답 전체가 동일하고, 21명은 20+1 페이지로 나뉜다. 기한 만료·권한 회수·다른 계정·토큰 변경·번호 변경 후 늦은 응답·중단 신호를 무시하는 제공자를 포함한다.

운영에서는 **함수 정의·열 정보만 읽었다**. 고객 행 조회, 실제 후보 조회 RPC, 명함 전송, 고객 저장, SQL 적용, GitHub 업로드·병합·배포는 하지 않았다. 실제 기기·실계정·전체 PC/모바일 저장 결과 대사는 미검증이다.

## PC와 다른 점 / 남은 결정

신규 조회는 공통 서버 권한·연락처 원장을 사용하지만, 이번 UI 연결은 모바일 I-3다. PC의 입력 화면을 바꾸거나 기존 저장 경로를 이 조회로 대체하지 않았다. PC·모바일의 사람 연결 저장까지 완료됐다는 뜻이 아니다.

회사 귀속(현장별 소속 / 사람의 공통 소속)은 사용자 답변 대기다. 원본의 ‘같은 분?’은 안내문이며 선택 컨트롤이 없으므로, 동일인 선택·현장 연결의 승인 조작도 남아 있다. 필요한 저장·선택 계약은 `CLAUDE_MOBILE_CONTACT_CONTRACT_20261011.md`에 유지한다. 그 전에는 I-3 연락처 저장을 활성화하지 않는다.

기준 확인: GitHub `poursolution/netform-crm` master `ad209245d50bdc46569b9533fdcf3b601936f679`(#596). [Supabase 함수 보안 문서](https://supabase.com/docs/guides/database/functions)에 따라 빈 search_path·명시적 객체 경로·제한된 실행 권한으로 작성했다. 운영 적용 전에는 현재 서버 정의와 다시 대조해야 한다.
