# 코칭 목록 쪽 번호 및 남은 완료 근거 연결

기준: netform-crm `aeb74885730341d0a651d028f04fb55b852d448c`.

## 이번 기능 수정

대표의 2026-10-05 전체 목록 지침에 따라 코칭 창의 `나머지 n건 전체 보기`를 공용 `ListPager`로 교체했다. 현재 코칭 창의 사유별 목록, `repWindowOff` 뒤 사람별 상세 목록, 두 새 창을 쓰지 않는 이전 문제현장 목록에도 적용했다. 한 쪽 최대 20건, 묶음별 쪽 상태, 필터/기간/담당자 변경 시 첫 쪽, 대상 감소 시 마지막 유효 쪽으로 보정한다. 다른 쪽의 열기 버튼은 실제 그 쪽의 대상에 연결된다.

코칭 초안은 쪽 이동 중 유지한다. 기존 총계와 묶음 요청은 전체 대상을 기준으로 유지한다. 쪽당 20건이 코칭 대상 20건이나 발송 상한을 뜻하지 않는다. 기존 현장 전체보기 바로가기는 오늘 업무로 이동하는 기능이므로 유지한다. CSS, 카드/창/행 규격과 공용 ListPager 디자인은 수정하지 않았다. 새 상세 진입 경로를 만들지 않았다.

## 검증

- 기존 브라우저 검사 두 개에서 합성 45건을 20/20/5건으로 대조.
- 마지막 쪽 실제 대상 열기, 재개방/기간 변경 초기화, 원자료 감소 시 유효 쪽 보정, 초안 보존 검증.
- 이전 문제현장 경로도 쪽 번호 및 페이지별 상세 대상 캐시를 확인.
- 기존 저장 확인·실패 복구·묶음 요청과 화면 규격 검사는 유지.
- 운영 고객 저장·요청 발송은 하지 않음. 로컬 검증은 운영 배포 완료를 뜻하지 않음.

## 다음 단계: 코칭 당시 대상과 완료 근거

#543은 서버 저장 확인, #544는 목록과 코칭의 현재 첫 연락 대상을 통일했다. 두 변경 모두 과거 코칭 당시 대상 ID 저장이나 실제 완료 증빙을 구현한 것은 아니다.

현재 `rep-window.js coachLine/parse/past`는 주제·문장·지표 수치를 관리자 코멘트로 저장하고 지난 코칭을 현재 지표와 비교한다. 대상 ID가 없는 과거 코칭을 현재 명단에서 임의 복원하면 안 된다. 숫자가 줄거나 날짜를 뒤로 미룬 것을 실제 고객 업무 완료로 취급하면 안 된다.

후속 연결에 필요한 계약:

1. 저장한 코칭 자체의 ID/버전, 코칭 당시 대상 종류와 ID, 당시 담당자 ID, 기준 시각·필터·판정 버전·완료 조건을 보존한다. 현재 텍스트를 숨은 JSON 저장소로 바꾸지 않는다.
2. 원래 대상 = 해결 + 미해결 + 근거 있는 제외 + 확인 불가로 대조한다. 신규 유입은 원래 대상에 추가하지 않고, 재배정·삭제·조회 권한 부족도 완료로 간주하지 않는다.
3. 입력 보완 완료와 실제 고객 응대 완료를 구분한다. 응대는 대상·연락 결과·저장 시각/이력이 필요하다. 재예약은 원래 기한과 변경 사유·이력을 남긴다.
4. 서버의 기존 코멘트 저장/조회 계약과 동시 수정 방지를 확인한 뒤 SQL·허용 목록·오류 이름·Release 게이트를 함께 준비한다. 이번 PR에는 SQL과 서버 칼럼 추가가 없다.
5. Claude는 기존 코칭 위치에서 `현재 지표 비교`, `당시 대상 처리`, `관리자 확인`의 표시를 결정한다. Codex는 표시 위치·창 규격·새 UI를 결정하지 않는다. 서버 연결 전 자동 확인을 실제 완료 검수로 표현하지 않는다.

범위 제한: 이번 PR은 코칭 작업 목록의 페이지 처리 수정이다. 단계 체류/활동 정체의 분류, 단계별 건수 차이를 이탈로 표현하는 문제, 약속 주체와 완료 근거는 후속 과제이며 해결됐다고 표시하지 않는다.
