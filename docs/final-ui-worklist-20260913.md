# CRM 최종 UI 작업목록 — 운영 배포 전

운영 배포는 이 목록의 로컬 검증이 끝난 뒤 한 번만 수행한다. 이 문서는 화면 변경을 다시 만드는 목록이 아니라, 이미 반영된 기능과 남은 운영 위험을 구분하는 최종 체크포인트다.

## 상세화면 완료 항목

- 문의는 연결 Deal이 있어도 문의 상세로 열리고, 영업기회는 명시적으로 이동한다.
- 견적금액과 수주확정금액은 읽기 전용이며 견적 Version/계약·수주 절차를 정본으로 사용한다.
- 파이프라인 빠른상세의 활동·다음행동·단계전환 버튼은 한 번만 표시한다.
- Deal 개요는 현재 문제·Next·연락·최근 활동 중심이며 나머지는 탭으로 분리한다.
- 연락처는 보기와 편집을 분리한다.
- 관계관리 연락 기록은 전체 상세의 불필요한 중복 동선을 줄이고 다음 연락과 함께 저장한다.
- 고객자산 상세는 6개 탭으로 분리한다.
- 단계전환은 기존 활동·Next를 참고정보로 보여주되 근거를 임의 생성하거나 복제하지 않는다.
- 확장관리 관리창은 핵심 고객과 연락처를 먼저 보여준다.

## 검증 결과

- 전체 자동 회귀: 634개 / PASS 618 / FAIL 0 / SKIP 16.
- 브라우저 검증: 오늘업무, 견적문의 역할뷰, 파이프라인 상세·드릴다운·필터, 고객자산 페이지, 관계관리, 확장관리, 모바일 320/390px 모두 PASS.
- 브라우저 합성검증 중 실제 업무 데이터 저장: 0건.

## 운영 배포 전 남은 위험

1. SKIP 16개는 실제 Staging 계정·JWT·RLS 자격증명이 필요한 통합검증이다. PASS로 계산하지 않는다.
2. 실고객 문의의 구글시트→수집→담당자 동기화 대조는 n8n·잔디·구글시트를 변경하지 않는 범위에서 별도 검증이 필요하다.
3. 관계관리 원자적 저장 RPC는 로컬 후보와 adapter 연결까지 준비됐으나, Production 적용 여부는 UI 배포와 별개로 기록·롤백 조건을 확인해야 한다.

## 실제 동기화 대조에서 확인한 장애

- 현재 열린 Apps Script 프로젝트에는 `Code.gs`와 `appsscript.json`만 있고 `SupabaseSync.gs` 파일은 존재하지 않는다.
- 최근 7일 실행 기록은 0건이고 설치형 트리거도 0개다. 따라서 이 프로젝트는 현재 담당자→Supabase 동기화를 실행하는 프로젝트가 아니다.
- 편집기에 보였던 `SupabaseSync.gs` 정규식 오류 알림은 현재 프로젝트 파일 목록과 일치하지 않아 이 프로젝트의 확정 원인으로 사용하지 않는다.
- 실제 동기화 프로젝트 또는 n8n 실행 경로를 찾기 전까지 `구글시트 → 담당자 DB 반영`은 BLOCKED다. n8n·잔디·구글시트 데이터는 변경하지 않았다.

## 변경 금지 경계

- 운영 배포 전까지 `origin/master` push 및 GitHub Pages 배포 금지.
- n8n, 잔디, 구글시트 변경 금지.
- 실제 고객 담당자·금액·상태를 합성 테스트 목적으로 변경 금지.
- 사용자 소유의 기존 미커밋 파일을 이번 작업에 포함하지 않음.
