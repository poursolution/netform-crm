# [단계 8] Claude I‑1~I‑3 원본 연결 및 입력 보호

상태: **로컬 검토용 부분 구현 — 후속 연결 반영**. D 상담 내용의 말하기 진입, I1 직접 입력 전환, 새로고침 복구, C 연락처 줄의 I3 진입과 명함 인식 어댑터를 연결했다. 운영 배포·실제 음성 인식·명함 전송·연락처 저장은 실행하지 않았다.

## 이번 후속 저장 계약

최신 후속 작업은 **입력 보존·복귀와 최초 보관소 오류 후 재진입**이다. 읽기에 실패하면 기존 C·D를 유지하고 새로 시도할 수 있게 했으며, 무입력 I3는 보관 공간 부족에도 뒤로 갈 수 있다. 기존 디자인을 유지했고, 수정한 입력은 보존 검사 후에만 화면을 나간다. 변경 파일·검사·한계는 [입력 복귀 보고](MOBILE_INPUT_NAVIGATION_REVIEW_20261011.md)를 따른다.

이전 후속의 **기존 연락처 후보 읽기 전용 조회**는 유지한다. 번호 수정 시 경고가 남는 오류를 고쳤고, 부분 로딩 목록 대신 공통 권한 범위 조회를 연결했다. 기존 Claude 안내 줄만 갱신하며 I-3 저장은 계속 차단한다. 변경 파일·응답 계약·검사·남은 결정은 [연락처 후보 조회 보고](MOBILE_CONTACT_MATCH_REVIEW_20261011.md)를 따른다.

PC·모바일 공통 연락처 저장에서 생략한 동의·거부 값을 보존하는 로컬 후보를 추가했다. 공통 adapter·양 전송 계층·PC 입력 호출·SQL 마이그레이션과 검사를 포함한다. 승인 모바일 화면 구성은 유지했고, I-3 저장은 회사·기존 사람 연결 계약이 남아 있어 계속 차단한다. 서버 설치·운영 데이터 변경·배포는 하지 않았다. 해당 구현과 63개 기능 검사 및 브라우저 검사 결과는 [공통 저장 보존 보고](MOBILE_CONTACT_CONSENT_PRESERVATION_20261011.md)를 따른다.

## 연결한 동작

- 말하기는 명시적인 버튼 조작에서만 시작한다. 열기만으로 권한을 요청하거나 녹음하지 않는다. 뒤로·계정 변경·대상 변경·화면 이탈 때 종료하고 늦게 도착한 결과를 거절한다.
- 실패 후 남은 문장을 I‑2에서 고칠 수 있다. 부분 인식·길이 초과는 자동으로 완성 문장으로 취급하지 않는다. 직접 입력 이벤트와 기존 메모를 자동으로 이어 붙인 결과를 구분한다.
- 음성 원문을 인식기에서 300자로 먼저 잘라 버리던 문제를 수정했다. 기존 메모와 음성 후보를 합해 최대 10,000자까지 검토 초안에 보존한다. 상한 초과는 명시적 오류로 인식을 중단하며 보존한 부분을 확인하도록 한다. D에 반영할 때는 PC의 300자 상담 내용 제한을 그대로 적용하고 사용자가 직접 줄인 뒤 반영한다. 이 상한은 추가 서버 저장 필드나 모바일 전용 상담 규격이 아니다.
- `MobileEntry.captureInputDraft()` / `inputDraftCurrent()` / `applyInputDraft()`는 같은 계정·세션·영업건·초안인지 검사하고 **상담 내용만 기존 로컬 초안에 반영**한다. 결과·다음 업무·날짜·요청 선택을 유지한다. 저장 진행 중·이미 바뀐 초안·오래된 핸들은 차단한다.
- D에서 온 초안에 반영할 때는 기존 I‑2 버튼 자리에 `입력에 반영`, 하단 설명에 `응대 저장은 다음 화면에서`를 사용해 서버 저장과 구분한다. 직접 열린 예시의 `저장`은 비활성 상태다.
- 날짜 표현은 확인 후보로만 표시한다. 후보 선택만으로 실제 날짜·방문 완료·견적 요청·단계 변경을 저장하지 않는다.
- 명함의 O/0 혼동은 그대로 오류로 남기고, 올바른 번호로 고치면 원본의 정상 표시로 돌아온다. 연락처 저장 계약이 연결될 때까지 저장은 차단한다.
- 예전 `scanCard()`가 가짜 현장명을 번갈아 넣던 동작을 제거했다. 인식 완료라고 표시하거나 현재 현장명을 바꾸지 않는다.
- 새 모듈이 없거나 불러오지 못하면 구 모바일 UI를 대신 띄우지 않는다.
- D의 상담 내용 안에는 가이드 §14에서 명시한 `누르고 말하기`를 연결했다. 폴더5의 원본 소형 마이크 버튼을 추출해 사용하며, 과거 자동 결과·일정 채우기 동작은 가져오지 않았다. 지원하지 않는 기기에는 버튼을 숨기고 D 직접 입력을 유지한다.
- I1의 기존 상담 칸을 누르면 I2에서 직접 수정한다. 듣는 중에는 인식을 중단하고 늦은 응답을 거절한다. 새 `다음` 버튼이나 새 배치는 만들지 않았다.
- 새로고침 후 같은 계정·세션·영업건에서 변환문, 직접 수정값, 미확정 후보를 복구한다. 복구는 서버 저장이나 요청 완료가 아니다. 부분 음성은 다시 고치기 전 반영을 차단한다.
- 부분 음성을 복구한 뒤 새 음성을 끝까지 말해도 앞의 미확인 문장이 자동 확인되지 않도록 수정했다. 직접 고치기 전까지 확인 필요 상태를 재시작·새로고침 후에도 유지한다.
- D에서 다시 진입할 때 기존 초안 전체가 바뀌었으면 이전 변환문을 덮어쓰지 않고 두 초안을 보존한다. 성공적으로 반영하거나 명시적으로 취소하면 해당 검토 초안을 지운다.
- C의 기존 연락처 줄은 I3으로 연결된다. I3 기존 사진 영역에서 선택한 사진만 PC와 같은 `crm-ai/contact_card`에 전송하도록 구현했다. 읽는 동안 입력을 잠그고, 재인식 성공 때 기존 수동 수정값을 유지한다. 실패·취소·계정 전환·이전 선택창의 늦은 결과는 현재 입력을 덮어쓰지 않는다. 예시에서는 사진 전송을 차단한다.

## 추가·바꾼 데이터 필드

초기 I-1~I-3 연결에서는 서버 표·업무 데이터·권한·RPC를 변경하지 않았다. 이번 후속에는 공통 연락처 RPC의 로컬 SQL 후보를 추가했으며 운영에는 적용하지 않았다. 새 탭 범위 `sessionStorage` 키 `crm:mobile-input-draft:v1:`에 계정·세션·영업건·speech/card별 초안을 30분 보관한다. 텍스트·미확정 선택·인식 중단 상태·D 초안 기준만 저장하고 토큰·음성·사진·서버 완료 증거는 저장하지 않는다. OCR 결과의 텍스트와 직접 수정 필드는 분리한다. 기기 보관 실패 때 현재 입력을 유지하고 실패로 표시한다. 앱/탭 종료 후 복원은 sessionStorage 보존 여부에 따라 달라지며 보장하지 않는다.

사용자가 명시적으로 반영한 상담 내용은 기존 `MobileSaveJournal`의 해당 D 초안 `input.memo`만 갱신한다. 결과·날짜·고객 약속·관리자 요청 선택을 유지하며 실제 응대 저장은 D에서 별도로 확인한다.

## PC와 다른 점 / 미연결 계약

PC의 `contact_card` 인식 경로에 연결할 어댑터와 버튼 경로를 구현했으며 실제 서버 인식은 미검증이다. 출력에는 회사명·필드별 불확실 원문이 없다. 현재 `contact_upsert`는 번호 기반 person_key로 기존 사람 정보를 갱신할 수 있고, 운영 코드에는 동의 값을 생략하면 false로 정규화하는 문제가 있다. 이번 로컬 후보에서는 이 부분을 수정하고 공통 저장 계약과 검사까지 준비했다. I‑3의 **기존 사람 선택 후 현장 연결**을 보장하려면 명시적 연락처 ID·연결 의도·회사 필드·기존 수신동의 보존 계약부터 맞춰야 한다. 번호 일치만으로 사람을 합치거나 기존 정보를 덮어쓰지 않는다. 연락처 저장은 계속 비활성이다.

추가 소스 검토에서 같은 `contact_upsert`의 9/7·9/8 SQL 경로가 서로 다른 것을 확인한 뒤, 운영 PostgreSQL의 함수 정의·열·인덱스를 읽어 대조했다. **현재 운영은 9/7 go 계약으로 분기하며 9/8 연락처 함수는 설치돼 있지 않다.** 이를 운영 저장 오류로 보고하지 않는다. 실제 설치 코드에도 생략한 동의 값 교체와 현장명 기준 활성 연결 고유키 `(person_key, site_name)`가 남아 있어, 기존 사람·동의·복수 영업건을 보존하는 공통 계약 보완은 필요하다. 고객 행 조회·저장 함수 실행·운영 변경은 하지 않았다.

상세 근거: [입력 계약 점검](../review-preview/STAGE8_INPUT_CONTRACT_AUDIT_20261011.md), [연락처 저장 계약 인수인계](CLAUDE_MOBILE_CONTACT_CONTRACT_20261011.md). 뒤 문서는 확인된 코드와 필요한 합의를 구분하며, 운영 마이그레이션이나 새로운 화면을 확정하지 않는다.

## Claude 인수인계 / 디자인 미결정

원본과 가이드 재대조로 이전 문서의 두 해석을 정정한다. D의 말하기 위치는 가이드 §14와 그림 설명에 명시돼 있고, 명함 사진 영역도 기존 원본에 있어 별도 디자인을 기다릴 필요가 없다. 아래만 남아 있다.

1. I‑2 날짜 확인·후속 후보의 실제 저장은 현재 D의 공통 업무 입력에서 한다. 후보 선택만으로 날짜·업무를 저장하지 않는다.
2. I‑3 진행·실패는 기존 사진 영역·설명문 안에서 표시한다. 새 촬영 화면을 만들지 않고 기기의 파일/촬영 선택을 사용한다. 실기기 권한·인식 품질 확인은 남아 있다.
3. I‑3 연락처 저장은 위 공통 사람·현장·동의 계약 정리가 선행돼야 한다.
4. 원본 I‑2에는 11.5px 설명과 10.5px 배지가 있어 가이드의 최소 12px와 충돌한다. 이번에는 제공된 그림을 유지했다. 10.11(금) 같은 예시의 날짜 오류는 확정 일정으로 사용하지 않는다.

**8단계 전체 완료 또는 운영 사용 가능으로 표시하지 않는다.** 승인 원본의 화면 연결과 입력 보호까지 준비한 상태다.

## 후속 — 일반 뒤로가기와 보관 실패

명함 입력의 일반 뒤로가기가 명시적 취소와 같은 삭제 경로를 사용하던 오류를 수정했다. 보관 실패·동시 수정 충돌 시 현재 입력 화면을 유지하고, 같은 영업건의 버전이 바뀌어도 이전 초안을 읽기만 해서 삭제하지 않는다. 계정·대상 변경 후 빈 화면에 남는 문제와 페이지 이탈 중의 자원 정리도 보완했다. 원본 스타일과 입력칸은 변경하지 않았다. 상세 수정·검증·한계는 [입력 보존과 화면 복귀](MOBILE_INPUT_NAVIGATION_REVIEW_20261011.md)에 기록했다.
