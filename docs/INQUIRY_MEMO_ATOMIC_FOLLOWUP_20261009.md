# 미완료 약속과 다음 할 일의 원자적 저장

대상: `poursolution/netform-crm`. 기준 master `5de120f26c2861fd398d301e17e9aba03c38a857` (#537).

## 문제와 변경

기존 `inquiry-memo.js`는 미완료 판단 전에 `InquiryCommand.run('next_set', …)`을 호출했다. 반환값 `true`는 전송 대기열 접수이며 서버 저장 완료가 아니다. 다음 할 일과 약속 판단 중 하나만 저장될 수 있었다.

UUID 문의의 미완료 판단만 `crm_inquiry_memo_followup_v1` 한 요청으로 보낸다. 판단, 다음 할 일, 감사 기록 두 개, 요청 영수증을 한 트랜잭션으로 저장한다. 완료·확인 불가·통화 날짜 보완은 기존 RPC를 유지한다. 파이프라인·디자인·HTML·CSS·표시 위치는 바꾸지 않는다.

- 기존 할 일의 ID·유형·담당·전체 기한 시각을 유지하고 제목에 확인할 약속을 포함한다. 이미 지난 기한도 오늘로 바꾸지 않는다. 새 할 일만 한국시간 오늘 날짜로 생성한다.
- 서버의 열린 할 일이 화면의 ID·제목·유형·한국 날짜와 일치하는지 잠금 안에서 확인한다. 여러 열린 할 일, 서버 확인 없는 로컬 업무, 담당 변경·종결·휴지통은 덮어쓰지 않고 거절한다.
- 응답을 받기 전에는 로컬 다음 할 일·판단·완료 이력을 바꾸지 않는다. 응답의 문의·요청·약속·결과·다음 할 일을 모두 검증한다.
- 응답 유실은 같은 화면 세션에서 동일 요청 ID와 본문을 보존해 사용자가 재시도한다. 자동 반복 전송은 추가하지 않는다. 같은 세션의 다른 판단은 이 요청 확인 전까지 보류한다. 새로고침 뒤에는 서버 자료를 읽고 새 요청을 만들며 이전 완료를 추정하지 않는다.
- 서버 재전송은 최신 판단과 현재 할 일이 여전히 일치할 때만 성공을 돌려준다. A→B→A, 다른 본문/작성자, 판단만 저장한 구형 요청 ID 재사용은 거절한다.
- 기존 next_actions 변경 신호·개인 업무 예약 트리거는 그대로 동작한다. 새 n8n 경로·반복 실행·외부 발송은 추가하지 않는다.

## 설치·배포 순서

1. #537의 영수증 버전 `sql/inquiry-memo-review-v1-20261008.sql` 설치 여부 확인.
2. `sql/inquiry-memo-followup-v1-20261009.sql` 적용. 신규 비공개 표는 `crm_security.inquiry_memo_followup_receipts`, 신규 공개 RPC는 `crm_inquiry_memo_followup_v1(jsonb)`이다. 고객 업무 칼럼 추가·과거 자료 재작성은 없다.
3. RLS, 익명 실행 거절, 직접 표 접근 거절, 현재 담당/관리자 검사를 확인.
4. 같은 PR의 허용 목록(`pc-manager-transport.js`), 오류 이름(`pc-error-state.js`), 기능 파일을 함께 배포한다. `OpsStore.has` → `CRMRelease.has` 게이트가 설치되지 않은 RPC를 막는다. 구형 분리 저장으로 되돌아가는 fallback은 없다.
5. 합성 데이터로 실패·재시도·기한 보존을 확인한다. 실제 고객 판단을 테스트 목적으로 저장하지 않는다.

이 문서는 로컬 구현 명세다. 운영 SQL 적용·병합·배포 완료를 뜻하지 않는다. 배포 전 승인 및 현재 master/운영 설치 상태를 확인해야 한다.

## 검증

`tests/inquiry-memo-atomic.test.cjs`: PGlite에서 두 쓰기와 감사 기록·영수증의 전체 롤백, 중복 방지, 과거/미래 기한 보존, stale snapshot, 다른 담당·종결·휴지통·미로그인·직접 접근 차단을 검증한다. VM에서는 ACK 전 불변, 잘못된 응답 거절, 동일 요청 재시도, RPC 미설치 시 분리 저장 차단을 검증한다.

기존 `inquiry-memo-followup`, `inquiry-memo-ack`, `inquiry-memo-receipts` 검사도 유지한다. 테스트 자료는 모두 합성 자료다.

## 제한·복구

이 기능 배포 이전 구형 브라우저는 기존 분리 저장 경로를 사용할 수 있다. 그 경로의 과거 부분 저장이나 모든 브라우저 대기열이 정리됐다고 주장하지 않는다. 새 버전은 미완료 저장에 신규 RPC를 요구한다.

장애 시 신규 RPC를 CRMRelease에서 비활성화해 추가 저장을 중단한다. 영수증·판단·업무·감사 기록은 삭제하지 않는다. 구형 JS로 되돌리면 분리 저장 결함이 재발하므로 단순 코드 롤백 대신 수정 배포한다.
