# [단계 1] 모바일 기능 후보 통합 검증

## 한 일

최신 master `0b7852e8824abf3740bb12b10b227ee7e3f84c59`와 누적 로컬 후보를 함께 사용해 **15개 검사 묶음을 실행했고 모두 통과**했다. 각 실행의 종료 코드·소요 시간·로그와 검사 대상 파일 해시를 `stage1-regression-result.json`에 보관했다. 과거 통과 횟수를 합산해 이번 실행 결과로 대신하지 않았다.

이 결과는 로컬 클라이언트 통합 검증이다. GitHub 필수 CI, 운영 SQL 설치, 운영 권한·트리거 및 실기기 검증의 완료를 뜻하지 않는다.

## 바뀐 파일

- `run-stage1-regression.cjs`: 같은 후보로 기존 검사 15개 묶음을 실행하고 결과·로그를 보관하는 실행기.
- `stage1-regression-result.json`, `stage1-regression-logs/`: 이번 실행 근거.
- 본 문서·진행상태·후보 패치·검증 manifest.

이번 통합 검증에서 앱 기능 코드·디자인·서버 SQL은 추가 수정하지 않았다.

## 추가·바꾼 데이터 필드

없음. 합성 응답과 큐를 사용하며 고객 원자료를 저장하지 않았다.

## PC와 다른 점

PC·모바일 공통 입력과 일정은 검사한 시나리오에서 일치했다. 모바일의 복합 요청 입력과 견적 v3 연결은 아직 다 완성되지 않았으므로 전체 CRM의 완전한 일치를 주장하지 않는다.
