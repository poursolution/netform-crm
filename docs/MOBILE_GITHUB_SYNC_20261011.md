## 반영 범위

- Claude 승인 원본을 사용하는 모바일 A~H, 입력 지원, 견적 9화면과 기존 데이터·저장 연결. 구 모바일 UI를 대신 보여 주는 경로를 차단한다.
- 승인 A 문의 카드 → 승인 D 공통 입력 → PC와 같은 문의 응대 저장, 기존 일정 보존 및 부분 실패 복구. 문의를 가짜 영업건으로 만들지 않는다.
- A에서 표시한 관리자 요청 하나만 확인하고, D에서 선택한 요청의 결과만 처리한다. 부재·번호 오류를 실제 연결이나 요청 전체 완료로 판단하지 않는다.
- 원본 전체에서 확인한 오늘 동선 전환·지도 구성과 방문 결과 진입을 연결한다. 없는 계정 메뉴나 옛 헤더를 추가하지 않는다.
- 승인 D 방문 기록은 실제 원일정·계정·영업건을 이어받고, 원일정을 자동 완료하지 않는다. 공사 정보 편집과 실제 견적 접수는 아직 연결되지 않아 차단한다.
- PC 문의 목록·오늘 업무·상세의 비동기 ACK 및 복구를 유지한다. 늦은 응답이 다른 대상 입력을 비우지 않으며 재시도는 같은 요청 번호를 사용한다.
- 최신 Claude PC 견적 코드는 보존한다. [master #596 대조](MOBILE_MASTER596_INTEGRATION_20261011.md)를 따른다.

## 서버 설치와 배포 상태

사용자가 앞서 승인한 **연락처 동의 보존·일정 보존·문의 응대 확인 SQL 3개**는 운영에 설치·권한 검증됐고 관련 서버 설정이 활성화됐다. 그때 확인한 5개 public RPC·3개 private helper 및 79개 기존 컬럼 호환성은 [서버 적용 기록](MOBILE_INQUIRY_D_DEPLOYMENT_BLOCKER_20261011.md)에 남아 있다. 고객 데이터 일괄 수정이나 실제 메시지 발송은 하지 않았다.

추가 파일 `sql/inquiry-milestone-preserve-v1-20261011.sql`은 **로컬 구현·합성 검사만 완료했고 운영에는 설치하지 않았다.** 기존 3개 SQL의 승인 범위를 넘는 추가 설치로 자동 승인 검토에서 차단됐으며, 별도의 명시적 승인 대기 상태다. 이 문서 갱신으로 SQL을 실행하지 않았다.

이 추가 계약은 일정 보존을 켠 상태에서 **기존 PC 문의 방문·견적 사실 저장을 유지하는 선행조건**이다. 미설치 또는 비활성 상태에서는 입력을 보존하며 저장을 거절하고, 기존 일정을 교체하는 옛 저장 경로로 돌아가지 않는다. 이 차단은 데이터 손실을 막지만 기존 PC 기능이 제공된다는 뜻은 아니다. 따라서 계약 설치·활성화 및 필요한 배포 검증이 완료되기 전에는 기능 보존을 보장한 병합·운영 배포 완료로 보고하지 않는다. 클라이언트 보호를 끄거나 서버 게이트를 우회하지 않는다.

승인 프런트엔드는 아직 운영 배포 완료로 확인되지 않았다. 이전 운영 확인에서는 구 모바일 자산이 로드됐으며, 이후의 GitHub 업로드·로컬 조립·합성 화면 검사는 운영 교체의 증거가 아니다.
