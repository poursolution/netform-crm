2026-10-11 로컬 합성 브라우저 전체 127그룹을 원래 동시성 4로 실행했고 **113 통과 / 14 실패**였다. 이는 후속 수정 전 실행 결과이며, 수정한 일부 검사 통과를 전체 재실행 성공으로 바꾸어 표시하지 않는다. GitHub head `8649dd5`의 필수 Quality Gate도 실패했다.

### 실제 기능 수정

- 문의 목록·오늘 업무·문의 처리창의 일부 경로가 옛 동기 저장을 호출했다. `InquiryListV3.record`, `InquiryWorkbench.saveProcess`, 오늘 업무의 호출자를 공통 `PCInquirySave`와 비동기 ACK 확인에 연결했다. 기존 일정 충돌은 기록 전 차단하고, 자유문장을 실제 고객 연결로 추정하지 않는다.
- 영업건 상세는 활동 기록 ACK 후 재렌더링되면 일정 저장이 미완료인데도 응대 입력을 닫을 수 있었다. 진행 중이거나 복구할 저장 정보가 남아 있는 입력은 유지하고 전체 저장 성공 뒤에만 닫는다.
- 기존 PC 문의 v4/v3/상세 v3 검사는 실제 활성화 상태에서 공통 합성 RPC를 사용하도록 갱신했다. 옛 `pushWrite` 호출 여부 대신 정확한 연락 ACK·일정 보존·부재와 연결 구분·실패 입력/같은 요청 재시도를 검증한다.

### 아직 해결하지 않은 실제 제한

1. 승인 모바일의 방문/공사 시기/견적 요청, 오늘 동선, 비밀번호 변경 진입 3개는 그대로 남아 있다. 위치는 [Claude 진입 인수인계](CLAUDE_MOBILE_APPROVED_ENTRY_GAPS_20261011.md)에 기록했다.
2. 새 보존 기능을 켠 PC의 기존 방문·견적 저장도 `protectLegacySchedule`이 차단한다. 이는 단순 검사 fixture 오류가 아니다. 기존 `inquiry-flow-v1`의 `quote_send`는 열린 다음 업무를 일괄 취소하고, `visit`은 동일 종류 방문 일정의 날짜·완료를 덮어쓸 수 있다. 업무 ID·원래 기한·변경 사유·완료 근거·재시도 영수증을 보존하는 서버 계약 연결 전에는 보호를 제거하지 않는다. 따라서 inquiry-detail-v2/flow의 방문·견적 성공 검사는 미해결로 유지한다.
3. day-zones의 실제 행 클릭 실패는 변경 전 master #596 소스로 같은 환경에서 실행해도 동일하게 재현됐다. DOM 이벤트만 호출하면 경로가 작동했지만 실제 포인터 클릭 검증을 대체하지 않았다. 원인은 미확정이며 통과로 처리하지 않는다.
4. 견적 공통 RPC 4개는 일정/응대 SQL 설치 후 운영 카탈로그에서도 미설치였다. 버전·금액·PDF 및 계산/저장 계약의 남은 문제는 [견적 서버 인수인계](CLAUDE_QUOTE_MOBILE_SERVER_CONTRACT_20261011.md)에 추가했다.

이번 기능 수정은 디자인·CSS·배치·새 화면을 바꾸지 않는다. 운영 고객 자료 저장이나 메시지 발송도 하지 않았다. 서버 설치·활성화 완료와 새 모바일 프런트엔드 배포는 별개이며, 이 PR은 계속 Draft다.
