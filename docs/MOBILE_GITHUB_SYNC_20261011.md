# 모바일 승인 디자인 구현 — GitHub 검토본

사용자가 요청한 누적 모바일 작업의 검토용 통합본이다. 기준은 master `ad209245d50bdc46569b9533fdcf3b601936f679`(PR #596). 운영 배포나 모든 기능의 완성을 뜻하지 않는다.

## 포함 범위

- Claude 승인 원본을 사용하는 모바일 셸·오늘·내 현장·상세·상담 입력·등록·일정·단계 업무·마감 및 입력 지원 화면. 이전 모바일 UI를 표시하는 대체 경로를 차단한다.
- source44 견적 v3의 모바일 9화면: 요청, 진행, 도착, 두 안, 이력, 간단견적, 새 기준, 공법견적, 제출금액. 원본 프레임과 선택·복귀·미전송 초안을 연결한다.
- PC·모바일 공통 응대 결과, 기존 일정 보존, 관리자 요청의 항목별 완료 근거, 저장 실패·늦은 응답·중복 저장 방지 계약 및 SQL 후보.
- 말하기·명함 검토의 입력 보존, 기존 연락처 후보 조회, 생략한 동의 값 보존, 전송 대기 구분.
- K1 날짜 선택은 승인 원본의 날짜 시트를 사용한다. K1 공종·K4 안의 선택은 20건 페이지 이동 중에도 유지한다.
- 최신 Claude PC 견적 기능은 보존한다. 통합 근거는 [master #596 대조](MOBILE_MASTER596_INTEGRATION_20261011.md)에 기록했다.

## 운영 반영 상태 — 2026-10-11 재확인

PR #597은 Draft이고 운영에 배포되지 않았다. 실제 운영 `mobile.html`은 기존 `mobile-v2.js` / `mobile-hub.js`를 읽고 있으며, 승인 화면의 `mobile-approved-boot.js` / `mobile-guide-shell.js`는 포함하지 않는다. 따라서 GitHub 업로드·합성 미리보기·로컬 검사 통과를 운영 화면 교체 완료로 설명하면 안 된다.

이번 GitHub 후속 반영에서 연결한 범위는 다음과 같다.

- 승인 A 문의 카드 → D 입력 → PC와 같은 문의 저장 계약 → 부분 실패 복구 경로. 문의를 가짜 영업건으로 바꾸지 않는다.
- 승인 A/B/C의 실제 관리자 요청 조회. 카드에 표시한 요청 하나만 확인 처리하고, 같은 영업건의 다른 요청은 일괄 확인하지 않는다.
- 이전에 저장된 관리자 보기 값은 서버가 허용한 rep 권한이 있을 때만 정리한다. 권한을 새로 부여하지 않는다.
- 승인 글꼴과 라이선스를 운영 조립 자산과 필수 해시 검증에 포함한다.

후속 사용자가 서버 설치·검증·활성화를 명시 승인했다. 검토한 연락처 동의 보존·일정 보존·문의 응대 확인 SQL 3개를 운영 DB에 설치했으며, 5개 public RPC·3개 private helper 본문과 권한, 기존 79개 컬럼 호환성을 확인했다. 일정·문의 서버 설정은 `enabled=true`로 활성화했다. 고객 데이터 일괄 수정과 메시지 발송은 하지 않았다. 이 서버 적용은 모바일 화면의 병합·배포 또는 실고객 저장 검증 완료를 뜻하지 않는다. 설치 이력과 검증 범위는 [서버 적용 기록](MOBILE_INQUIRY_D_DEPLOYMENT_BLOCKER_20261011.md)에 보존한다.

남은 실제 진입 누락은 다음과 같다. 검사 기준만 바꿔 PASS로 처리하지 않는다.

- 방문 결과 → 공사 시기 보완 → 견적 요청의 승인 화면 저장 경로가 아직 연결되지 않았다.
- 오늘 동선과 비밀번호 변경은 엔진이 있어도 승인 화면에 여는 위치가 없다. 새 위치를 임의로 만들거나 옛 화면을 복원하지 않는다.
- 견적 계산·최종화 및 명함의 실제 연락처 저장은 아래 공통 서버 계약 연결 제한을 유지한다.

승인 A/B/C/D 원본 대조나 저장 일치 검사는 그 검증 범위만 증명한다. 모바일 전체 기능·실계정 저장·운영 배포 완료를 증명하지 않는다.

## 이번 확인 결과

- 공통 계약 전체 실행: 226 + 535 = 761개 통과. 이후 부팅·요청 연결과 글꼴 조립 수정은 아래 집중 검사로 확인했다.
- 문의 A→D 및 재시도 브라우저: 9그룹 통과.
- 관리자 요청 D 처리·A의 단일 확인: 12그룹 통과. 부재·번호 오류는 완료 처리하지 않는다.
- 인증·실제 요청 조회 연결: 8개 통과. 합성 인증/RPC이며 운영 쓰기는 없다.
- 글꼴 조립·해시·누락/변조 검증: 12개 통과.
- 일정·응대 SQL: 로컬 합성 PostgreSQL 61개 통과. 이후 사용자 승인으로 운영 설치·권한 검증·서버 설정 활성화를 실행했다. 실제 고객 기록을 저장하는 검증은 수행하지 않았다.
- 원본 A/B/C/D와 구 모바일 표시 차단 검사는 디자인 승인 원본 대조이며 운영 배포 증거가 아니다.

전체 CI 통과나 운영 모바일 교체 완료로 보고하지 않는다. 실제 남은 실패는 방문/정보 변경, 동선, 비밀번호 변경 진입 검사에 보존한다.

## 검토 방법

저장소에서 `npm ci` 후 `node review-preview/server.cjs`를 실행하면 합성 검토 서버가 127.0.0.1:8767에 열린다. 이 서버는 외부 연결과 쓰기 요청을 차단한다. `mobile.html?demo=1&screen=A` 또는 `screen=K-1`, `screen=I-3`으로 확인한다. 원본 디자인 미리보기 8766과 구분한다.

집중 검사는 `node review-preview/verify-quote-calendar.cjs`, `node review-preview/verify-quote-calendar-browser.cjs`, `node review-preview/verify-quote-pagination-selection.cjs`, `node review-preview/verify-quote-draft-recovery.cjs`, `node review-preview/verify-no-legacy-boot.cjs`로 실행한다. 브라우저는 Playwright Chromium 또는 `PLAYWRIGHT_EXECUTABLE_PATH`를 사용한다.

소스·테스트·최소 합성 fixture·인수인계 문서만 게시한다. 운영 조회 원본, 자격정보, 임시 캐시, 중간 패치, 개인 로컬 경로에 의존하는 과거 생성 스크립트는 게시 대상에서 제외한다. 단계별 과거 보고의 로컬 캡처/결과 파일은 그 당시 검증 근거이며 이번 저장소 파일 목록과 같지 않을 수 있다.
