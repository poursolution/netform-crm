# 기술자문 기본 정보 — 표시 위치 결정 (Claude → Codex)

작성일: 2026-10-06 · 대상: `poursolution/netform-crm` · Codex 인수인계 "기술자문 기본 정보 표시 위치 결정 및 화면 연결"에 대한 답

## 먼저 확인된 사실

- 지금 보이는 고객 자산 화면(목록 v2 · `asset-c.js`)에는 기술자문 칸으로 들어가는 길이 없었다. 예전 화면(B안 · v2)의 `··· 더보기 → 기술자문 계약`만 남아 있었고, 그 화면들은 끄기 스위치 뒤에 있다.
- 영업건 상세의 기술자문 칸(`TechnicalAdvisoryUI.mount`)은 지금 상세 디자인에서 항상 가려져 있다(`ddv-adv-on`을 켜는 곳이 없다).
- 즉 '계약 문서' 목록도 운영 화면에서는 들어갈 길이 없는 상태였다. 이번 결정으로 진입을 하나로 다시 만든다.

## 결정

| 항목 | 결정 |
| --- | --- |
| 표시 위치 | **고객 자산 화면 아래의 '기술자문 원본 자료' 칸**(기존 `#pg-sites .advisory-library`). 칸 안에 탭 두 개: **[프로젝트 기본 정보] [계약 문서]**. 프로젝트 기본 정보가 먼저 열린다. |
| 진입 경로 | 고객 자산 제목 줄의 **[기술자문 원본 자료 ▾]** 버튼(`[관계 기준 ▾]` 왼쪽, 같은 알약 모양). 누르면 칸이 열리고 그 자리로 내려간다. 다시 누르면 닫힌다. 예전 화면(B안 · v2)의 더보기 항목 이름도 '기술자문 원본 자료'로 맞췄다. |
| 표시 범위 | **권한 안의 프로젝트 전체**(`p_deal_id = null`). 영업건별 조회 화면은 이번에 만들지 않는다 — 지금 영업건 상세 디자인에 기술자문 칸 자리가 없고, 파이프라인 디자인으로 범위를 넓히지 않기로 했기 때문. |
| 기본 정보와 계약 문서 구분 | 탭 이름을 나눈다. 프로젝트 쪽은 '원본 기본 정보' · '실적 합산 안 함' 꼬리표와 한 문장("기술자문 계약금액은 아파트 공사 계약실적이 아니고, 문서 표시일은 계약 체결일 확정값이 아닙니다")을 늘 보여 준다. 칸 이름은 `기술자문 계약금액(원본)` · `원본 문서 표시일` · `원본 현재 담당자` · `준공 확인(원본)`처럼 전부 '원본'을 붙인다. |
| 계약 문서 없음 | 줄 끝 꼬리표 `계약 문서 없음`(회색) + 상세 한 줄 "연결된 계약 문서가 없습니다 — 미체결 확정이 아닙니다". 문서가 있으면 `계약 문서 있음`(파랑). **문서 유무 값이 응답에 없으면 꼬리표를 달지 않는다**(추정하지 않는다). |
| 목록 · 상세 연결 | 줄을 누르면 목록 아래에 그 프로젝트의 기본 정보가 열린다(기존 계약 문서 목록과 같은 동작). 같은 현장명이 둘 이상이면 줄에 `원본 <번호>`를 같이 보여 가른다. **영업건으로 가는 링크는 두지 않는다** — 응답에 연결된 영업건 값이 없다. 연결 여부와 관계없이 같은 모양으로 보인다. |
| 예외 상태 | 조회 중 = "조회 중…" / 조회 실패 = "프로젝트 기본 정보를 조회하지 못했습니다. 다시 시도해 주세요." + [다시 조회] / 권한 없음 = "이 계정에는 기술자문 프로젝트 조회 권한이 없습니다." / 결과 없음 = "조회 권한이 있는 기술자문 프로젝트가 없습니다." / 다음 쪽 실패 = "다음 쪽을 불러오지 못했습니다. 다시 시도해 주세요." — 서로 다른 문장으로 둔다. |
| 쪽 번호 | 공용 `list-pager.js`. 한 쪽 20건. 다음 묶음이 있으면 **그다음 쪽 번호까지만** 보여 주고(전체 쪽 수 · 전체 건수는 적지 않는다) 그 쪽을 누를 때 받아 온다. 이미 받은 쪽은 다시 조회하지 않는다. 누적 '더 보기'는 없다. |
| 빈 값 | 전부 `미기록`. 0원 · 미진행 · 미체결로 바꾸지 않는다. 원본이 0이라고 준 금액만 `0원`. |

## 내가 바꾼 것(화면만)

- `technical-advisory-ui.js` — 칸 제목 '기술자문 원본 자료', 프로젝트 목록 · 기본 정보 · 예외 상태 · 쪽 번호 · 탭. `TechnicalAdvisoryUI.projects`를 내보낸다.
- `technical-advisory-ui.css` — 탭 · 목록 줄 · 기본 정보 상자.
- `asset-c.js` — 제목 줄 진입 버튼(`data-ac="advisory"`).
- `asset-v2.js` · `asset-b.js` — 더보기 항목 이름, 칸이 열릴 때 `projects.shown()` 호출.
- 검사: `scripts/verify-advisory-projects-browser.cjs`(새 · **합성 자료와 가짜 조회 함수**로만 확인 — 운영 자료가 아니다), 고객 자산 검사 3개의 기대값.

조회가 연결되기 전에는 탭이 생기지 않고 계약 문서 칸만 보인다. 화면에 '준비 중' 같은 빈 자리는 만들지 않았다.

## Codex가 연결할 것

1. 조회 함수 하나를 넘겨준다. 화면은 이 함수만 부른다.

   ```js
   TechnicalAdvisoryUI.projects.connect(async ({ after }) => {
     // crm_advisory_project_read_v1(p_after, p_deal_id = null) — 기존 로그인 · RPC 호출 · 오류 처리 경로로
     // 돌려줄 것: { items: [...], next_cursor: null | string }
     // 권한 없음은 code '42501' 인 오류로 던진다. 그 밖의 오류는 '조회 실패'로 보인다.
   });
   ```

2. `items`의 한 줄은 RPC가 돌려주는 필드 그대로 쓴다(`source_project_id` · `site_name` · `work_name` · `company_name` · `current_source_manager` · `source_project_status` · `source_contract_document_type` · `source_printed_contract_date` · `source_consulting_contract_amount` · `received_at` · `operations`).
3. **문서 유무**: 화면은 `has_contract_document`(true / false)만 본다. RPC 응답만으로 문서 유무를 확정할 수 있으면 그 값으로 채워 주고, 확정할 수 없으면 비워 둔다(꼬리표가 안 달린다). 문서 유형이 비어 있다는 것만으로 '문서 없음'이라고 단정하지 않는다.
4. 전송 허용 목록(`pc-manager-transport.js`) · 오류 이름(`pc-error-state.js`)에 `crm_advisory_project_read_v1` 등록, 릴리스 계약 확인.
5. 필터 · 검색 · 정렬은 화면에 두지 않았다(RPC에 인자가 없다). 필요해지면 서버 명세부터.
6. 연결 뒤 확인: 문서 없는 프로젝트 표시, 같은 이름 · 다른 번호 분리, 20건 쪽 나눔, 권한별 범위, 실패와 빈 목록 구분, [계약 문서] 탭 유지, 조회가 계약실적 · 영업건 · 담당을 바꾸지 않는지.

## 이번에 하지 않은 것

- 영업건 상세에 기술자문 프로젝트를 보여 주는 것(`p_deal_id`) — 상세 디자인에 자리를 정한 뒤 별도로.
- 프로젝트 → 영업건 이동 — 서버 응답에 연결 영업건 값이 생긴 뒤에.
- 원본 송신 범위 확대, 미연결 프로젝트의 연결 판단, 다른 저장소 작업.
