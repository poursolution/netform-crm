# KPI 요청 이력 준비 상태와 완료 근거 — 2026-10-10

상태: 배포 전 검토 초안. 기준 커밋: `94773d307938c936917be1548cea382458565dfa`.

## 구현 범위

- `kpi-b.js`: 요청 이력의 미조회·조회 중·실패·미연결·부분 조회를 구분한다. 준비되지 않은 이력으로 요청 전송 및 주간 결과 저장을 실행하지 않는다.
- `kpi-v7.js`: 기존 표시 위치에서 준비 상태를 안내하고 기존 요청·저장 버튼의 비활성 상태를 연결한다. CSS와 배치는 변경하지 않는다.
- 필터 변경으로 현재 대상에서 사라진 기존 요청을 완료로 세지 않는다. 완료 근거가 없는 요청은 미확인으로 남겨 처리율과 주간 저장에서 제외한다.
- WorkRequest의 명시적인 `done`·`replied` 결과는 계속 집계한다. 조회 중에는 빈 목록으로 확정하지 않는다.
- 기존 다음 행동 등록률, 문의 SLA, 쓰기 권한, 원본 이력은 유지한다.

## 배포 전에 해결할 제한

현재 `crm_kpi_action_list_v1`은 최대 200행을 반환한다. 응답이 200행이면 더 있는지 확인할 수 없어 부분 조회로 처리한다. 따라서 이 초안만 배포하면 그 계정의 KPI 요청과 주간 저장이 잠긴다. **전체 이력을 확인할 조회 계약·서버 검증을 추가하기 전에는 병합·배포하지 않는다.** 반복 전체 조회나 n8n 우회는 추가하지 않는다.

기존 `kpi_actions`에는 대상별 실제 완료 근거가 없다. 처리율을 다시 확정하려면 요청 당시 대상과 서버 완료 근거를 연결해야 한다. 현재 목록에서 사라짐·담당 변경·기간 제외는 완료 근거로 사용하지 않는다.

이번 변경은 요청 저장 성공 전에 성공 표시하는 기존 경로와 자동 저장 성공 표식의 시점까지 수정한 것이 아니다. 이 두 경로는 후속 검증 대상으로 유지한다. 신규 SQL·서버 필드·운영 데이터 수정은 없다.
