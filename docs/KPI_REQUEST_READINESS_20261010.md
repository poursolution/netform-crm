# KPI 요청 조회·저장 확인 — 2026-10-10

PR #542, 배포 전 검토. 기준 master: 94773d307938c936917be1548cea382458565dfa.

## 문제와 변경

요청 이력이 불러와지기 전에 빈 목록으로 판단하고, 최신 200행만으로 요청 여부를 판단했다. 저장 응답 전에 보냄을 표시했고, 필터에서 대상이 빠지면 업무 완료로 계산했다.

- kpi-b.js: 이력 전체 조회가 끝나야 집계·요청·주간 저장을 허용한다. 조회 실패·미설치·부분 조회는 미확인 상태다. 기존 목록에서 사라진 요청을 완료로 추정하지 않는다.
- crm_kpi_action_list_v2: 기존 인증 사용자 조회 권한을 유지한다. (created_at,id) 내림차순 커서, 첫 페이지 상한, 200행씩 조회한다. 클라이언트는 최대 50페이지(10,000행) 이후에도 남으면 부분 조회로 멈춘다. 중복 행·반복 커서·잘못된 응답은 거절한다. 매분 호출이나 n8n 경로는 없다. 신규 삽입이 첫 조회 상한보다 뒤라면 다음 새로고침에서 반영된다. 여러 HTTP 호출이 하나의 MVCC 스냅샷인 것은 아니다.
- crm_kpi_request_send_v1: 관리자 한마디와 요청별 이력 및 저장 영수증을 같은 트랜잭션에 저장한다. 기존 관리자/지사 저장 권한을 유지한다. 담당자 이름이 활성 계정 하나로 확인되지 않으면 거절한다. 기존 주간 코멘트에 서버에서 원자적으로 덧붙인다.
- crm_security.kpi_request_receipts: (actor_auth_uid,request_id)와 원 요청·응답을 보관한다. 같은 ID·같은 내용 재시도는 기존 응답을 반환하며, 내용 변경은 거절한다. 테이블 직접 접근은 차단한다. 이는 **전달 영수증**이며 고객 업무 완료 증빙이 아니다.
- kpi-v7.js, dash-b.js: 기존 버튼 동작은 서버 확인 후에만 성공 표시한다. 같은 함수를 쓰는 대시보드 기록 요청·컨트롤타워 요청도 비동기 응답을 기다린다. 실패한 담당자는 성공 인원에 넣지 않는다. 미배정 대상에게 보내지 않는다.
- 주간 자동 저장 표식은 저장한 주·개수와 ok를 확인한 뒤에만 기록한다. 실패 시 화면을 다시 그릴 때마다 자동 재시도하지 않는다. 수동 저장 또는 다음 접속에서 다시 시도할 수 있다.

## 기존 계산과 완료 근거

다음 행동 등록률, 문의 SLA, 운영 원자료, 단계, 디자인은 유지한다. WorkRequest의 done·replied는 기존 기준으로 집계한다. 별도 kpi_actions의 과거 요청에는 대상별 업무 완료 근거가 없으므로, 현재 대상에서 사라진 건이 있으면 처리율을 확정하지 않고 그 지표를 주간 저장에서 제외한다. 기존 이력을 수정하거나 일괄 완료 처리하지 않는다.

활동 기록률은 영업건, 담당별 요청은 인원 기준이다. 36-1-3을 제외 영업건 수로 해석하지 않는다.

## 적용 순서와 복구

1. 필수 CI 검사 확인 후 운영 반영 승인.
2. sql/20261009171018_kpi_request_history_and_ack.sql 적용. Supabase CLI가 생성한 마이그레이션 식별자를 사용하며 저장소의 수동 SQL 배포 경로에 둔다. 기존 두 표의 구조/원자료는 유지하고 조회 인덱스·비공개 영수증 표·RPC 두 개를 추가한다.
3. crm_release_manifest_v1에서 새 RPC 두 개 확인. 같은 PR의 전송 허용 목록·오류 이름·CRMRelease.has 게이트를 확인한다.
4. 프런트 병합·배포 후 읽기와 준비 상태 확인. 실제 담당자에게 테스트 요청은 임의 발송하지 않는다.

RPC가 없으면 기능은 대기한다. 이전 클라이언트용 v1 조회·저장 함수는 제거하지 않는다. 되돌릴 때 영수증·요청 이력은 삭제하지 않는다. 과거 완료 판정으로 되돌리는 기능 스위치를 복구 방법으로 쓰지 않는다.

## 검증

- Node/PGlite 회귀 검사 21개: 응답 지연, 399행/동일 시각의 커서 경계, 추가 삽입, 잘못된 커서, 이력 중복, 미설치, 권한, 저장 실패 전체 취소, 응답 유실 재시도, 담당자별 부분 실패, 주간 저장 응답과 재시도 상한, 기존 지표 계산.
- 로컬 브라우저 4개: KPI v7, 기존 KPI 버튼 경로, 측정 기준, 대시보드/컨트롤타워 요청. 합성 데이터와 가짜 RPC 응답으로 검사했으며 운영 반영 검증이 아니다.
- 기존 CI의 실패 3건은 과거 테스트가 ‘목록에서 사라지면 완료’, pushWrite 즉시 성공을 기대한 데서 발생했다. 그 검사는 검증된 저장 응답과 완료 근거 기준으로 갱신한다. 테스트 파일의 디자인 규격 검사는 유지한다.
- 실제 운영 DB에서 한 작업은 기존 함수 정의 조회뿐이다. SQL 적용·고객 요청 전송·운영 지표 저장은 하지 않았다.

## Claude 인수인계

고정 필터 높이·여백, 집계 단위 표시 위치, 요청 기간별 표시와 코칭 문구 배치는 Claude 담당이다. Codex는 CSS·배치·색·크기를 변경하지 않았다. 기존 위치에서 조회·저장 상태와 버튼 실행 조건만 연결했다. 과거 요청의 실제 완료 근거를 연결할 자리가 필요하면 별도 디자인 인계 후 구현한다.
