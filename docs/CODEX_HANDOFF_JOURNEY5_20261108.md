## 서버 몫

### 1. 끝난 수주 건의 계약일 · 착공일 · 준공일 저장
- 사실: 종료 건 저장 함수 `crm_deal_closed_info_update_v1`(CI_KEYS)에 이 칸들이 없어 상세에서 읽기만 된다(`deal-frame7.js` 끝난 건 날짜 줄).
- 필요한 일: 종료 건 저장 함수에 `contract_date` · `start_date` · `completion_date` 를 받는 칸 추가 + 권한(담당 · 관리자) + 감사 기록. 계약일 · 계약금액의 정본은 계약 원장이므로, 원장과 다르면 원장을 우선하고 화면에는 '확인 필요'로 보이게 할지 정해야 한다.
- 화면: 서버 함수가 생기면 Claude 가 수주 창 · 상세의 날짜 칸을 고칠 수 있게 연결한다(CRMRelease 게이트).

### 2. 수주 처리와 계약 원장의 연결
- 사실: 계약 체결은 DB 트리거가 원장에 기록하고, 변경 · 취소는 `crm_contract_sales_write_v1`(성과 분석의 관리자 화면)로만 쓴다. 수주(낙찰) 처리 `crm_deal_win_register_v1` 와 원장 행 생성은 별개다.
- 필요한 일: 수주 건 중 원장 행이 없는 건 수를 운영 DB 에서 세어 보고(읽기 조회), 계약 체결 기록이 빠지는 경로가 있는지 확인. 수정이 필요하면 SQL 은 대표가 Run.

### 3. 단계 순서(계약 · 시공 → 수주)
- 사실: `pipeline-stages.js` 정의상 계약 · 시공 단계가 수주보다 앞에 있다. 실제 흐름은 낙찰(수주) → 계약 → 시공이라 영업건 단계 띠의 순서가 실제와 다르다. 화면의 '문의 → 영업 → 계약 → 시공' 경로 한 줄(journey-path.js)은 이미 실제 순서로 보여 준다.
- 필요한 일: 단계 코드 · 그룹을 바꾸면 집계 · 목록 · 서버 전환 규칙이 모두 영향을 받는다. 바꿀지 대표 결정이 먼저이고, 바꾼다면 서버 단계 정의 · 전환 검증부터.

### 4. 계약 원장 전용 목록(결정 필요)
- 사실: 원장 목록은 성과 분석 안의 근거 표 · 관리자 '계약 변경 · 취소 기록' 창에만 있다. 영업건 상세의 계약실적 단추는 대표 지시로 금지돼 있다.
- 필요한 일: 전용 메뉴가 필요한지 대표 결정. 필요하면 목록은 한 쪽 20건 + 쪽 번호(공용 list-pager), 조회 함수는 기존 `crm_contract_sales_read_v2`.
