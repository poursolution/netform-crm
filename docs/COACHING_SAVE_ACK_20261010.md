# 코칭 저장 확인 수정 — 2026-10-10

기준: `poursolution/netform-crm` master `c75c867fdb7a196e67df06ccb66f94bb7e89314f`.

## 문제와 변경

코칭 저장과 완료 전환은 서버 응답 전에 브라우저 저장소를 수정했고, 코칭 창의 묶음 요청은 관리자 한마디와 KPI 요청을 따로 저장했다. 서버 실패 시 저장됨·요청함 표시가 실제 기록과 달라질 수 있었다.

- `crm.html`: 기존 코칭 저장 RPC의 응답에서 담당자·주차·내용·상태·서버 저장시각을 확인한 뒤 캐시와 화면에 반영한다. 완료 전환도 같은 경로를 사용한다. 동일 담당자·주차의 이 창 내 중복 클릭을 차단한다.
- `rep-window.js`: 저장을 기다리고 실패 시 입력을 보존한다. 기다리는 동안 바뀐 문장이나 다른 담당자의 창을 뒤늦은 응답으로 덮어쓰지 않는다. 묶음 요청은 #542의 `KpiB.requestLine`을 통해 관리자 한마디와 KPI 요청을 원자적으로 저장한다. 다음 행동 요청의 기존 `kpi:3`·담당자 대상 의미를 유지한다.
- `reps-v2.js`: 끄기 스위치 뒤의 기존 담당자 창도 저장 성공 응답 뒤에만 성공 알림을 표시한다.
- 기존 저장 RPC·허용 목록·배포 게이트를 사용한다. 추가 SQL과 서버 칸은 없다. 운영 원자료를 일괄 변경하지 않는다.

## 검증

합성 자료만 사용하는 검사에서 응답 대기, 서버 실패, 응답 담당자·주차·내용·상태 불일치, 이중 클릭, 로그인 계정 변경, 저장 대기 중 추가 입력, 다른 담당자 창으로 이동, 완료 전환 실패, 캐시 저장 공간 부족을 검증한다.

현재 창·이전 담당자 창·기존 관리자 화면의 브라우저 검사를 유지한다. 창 크기·배치·색상 검사는 그대로 두며 운영 요청·알림을 실제로 보내는 검사는 하지 않는다.

## 남은 사항 / Claude 연결

현재 디자인·위치·문구 구조는 유지한다. 코칭 시점의 대상 ID 고정, 해결·미해결·제외 근거 표시, 고객 약속과 코칭 약속 구분은 별도 기능 계약과 Claude의 화면 연결이 필요하다. 이번 변경은 이를 완료한 것으로 표시하지 않는다.

기존 코칭 본문 저장 RPC는 담당자·주차별 본문 전체를 교체한다. 서로 다른 브라우저/관리자의 동시 수정에 대한 버전 충돌 검사는 아직 없다. 이 PR의 중복 클릭 잠금은 같은 페이지 범위이며, 서버의 다중 작성자 충돌 제어를 대신하지 않는다. 신규 서버 변경 없이 기존 저장 경로의 성공 오표시를 먼저 수정한다.

운영 배포는 이 PR의 검사 결과와 별도 승인 후 진행한다.
