## 1. 무엇을 연결하는가 — 현장과 영업건을 구분

**확정:** 아파트가 같다는 이유만으로 모든 영업건을 합치거나 함께 단계 이동시키지 않는다.

| 연결 단위 | 의미 | 운영 규칙 |
| --- | --- | --- |
| 현장 | 같은 아파트·건물 | 이름이 달라도 주소·현장 근거를 대조해 기존 현장에 연결 |
| 영업건 | 특정 연도·공종·범위의 영업 기회 | 같은 현장에 여러 건 유지 가능. 공사 범위·기간·계약 근거로 구분 |
| 기술자문 관리 건 | 해당 영업건에서 파생된 기술자문 업무 | 기술자문 원본 프로젝트와 CRM 영업건의 연결을 보존 |
| 계약 | 기술자문·POUR 등 개별 계약 및 변경계약 | 각 계약의 원본 식별자·상대방·금액·날짜·이력 유지 |

**연동 통제:**

- 우선순위는 검증된 기존 식별자 연결 → 주소를 포함한 동일 현장 근거 → 공종·세부 범위·기간·계약 근거 대조다. 이름 유사도는 후보 추천에만 사용한다.
- 주소 누락, 같은 이름의 다른 지역, 서로 다른 동·공종·연도, 여러 계약 후보, 금액 불일치는 확인 대상으로 남긴다. 현재 담당자나 금액 하나만으로 연결하지 않는다.
- 같은 현장 연결이 확인됐더라도 같은 계약·영업건이라는 뜻은 아니다. **현장만 연결 / 영업건까지 확정 / 확인 필요**를 구분한다.
- 원본 프로젝트 ID와 계약 ID, CRM 현장·영업건 ID를 연결 근거와 함께 남긴다. 명칭 변경으로 새 현장이나 새 영업건을 만들지 않는다.
- CRM 영업건이 삭제됐거나 연결이 끊겼으면 검토 대상으로 둔다. 자동 복원·신규 생성·이름이 비슷한 다른 건으로 재연결하지 않는다.
- 이미 연결된 기술자문 관리 건이 있으면 재사용한다. 수주 저장, 재전송, 상태 갱신을 반복해도 관리 건을 중복 생성하지 않는다.
- 한 원본 프로젝트에 여러 공사가 묶였으면 공사별 적용 범위를 먼저 확정한다. 프로젝트 전체 상태를 여러 CRM 영업건에 무조건 전파하지 않는다.

## 2. 영업 결과와 현장 진행은 별도 기준

**확정:** 영업 결과가 확정된 시점과 준공된 시점을 혼합하지 않는다.

| 구분 | 답하는 질문 | 대표 값 |
| --- | --- | --- |
| 영업 결과·수주 유형 | 어떤 방식으로 영업이 성사됐는가? | 직접 수주 / 협약시공사 수주·기술자문 / 승인 타사 이관 수주 / 실주 |
| 현장 진행 | 지금 공사가 어디까지 진행됐는가? | 계약 진행 / 시공 중 / 준공 |
| 계약·대금 | 어떤 계약이 체결됐고 얼마가 청구·입금됐는가? | 계약 작성·서명·변경·취소 / 청구·입금·미수·정산 |

- 수주 처리에서 기술자문 발생을 확정하면 해당 영업건에 기술자문 관리 건을 연결한다. 기존 건이 없을 때만 생성한다.
- 기술자문 발생이 아직 예상이면 예상으로 남긴다. 계약 작성·서명 대기는 계약 체결 완료가 아니다.
- 수주 유형·낙찰 결과가 확정돼도 공사는 계약·시공 단계에서 계속 진행될 수 있다.
- 기술자문 준공으로 CRM이 수주 단계에 도달하는 것은 **운영 진행 표시**다. 별도의 수주·계약 실적을 다시 생성하는 사건으로 취급하지 않는다.

## 3. 기술자문 화면 → CRM 단계 반영

**확정된 흐름:** 기술자문에서 업무를 처리하면, 정확히 연결된 CRM 영업건의 운영 상태도 따라간다.

| 기술자문에서 확인한 사실 | CRM 운영 반영 | 함께 남길 정보 |
| --- | --- | --- |
| 계약 작성·발송·서명 진행 | 계약 단계 | 계약 진행 상태. 서명 완료와 구분 |
| 계약 체결 완료, 아직 미착공 | 계약 단계 | 체결 상태와 확인 가능한 계약일 |
| 실제 착공 또는 시공 진행 확인 | 시공 단계 | 실제 착공일, 공정률, 원본 갱신 시각 |
| 실제 준공 확인 및 준공일 존재 | 수주 단계 + 준공 완료 | 실제 준공일, 준공 근거, 원본 상태 |
| 대금 청구·입금·정산 처리 | 대금 상태만 갱신 | 청구·입금·미수·정산 정보 |
| 계약 취소·해지, 준공 취소, 상태 충돌 | 확인 필요 | 원본 상태와 사유. 자동 삭제·실주 전환 금지 |

**연동 통제:**

- '착공 예정일이 지났다'는 이유만으로 시공을 확정하지 않는다. 예정일과 실제 착공을 구분한다.
- 공정률 100%만 있고 준공 확인·준공일이 없으면 '준공 확인 필요'다. 임의 날짜로 수주 이동시키지 않는다.
- '정산 완료'나 입금만으로 준공을 추정하지 않는다. 준공돼도 미수가 있으면 대금 관리는 계속 남긴다.
- 상태 원본은 기술자문 시스템이다. CRM에는 원본 상태, 마지막 반영 시각, 연결 상태를 추적 가능하게 남긴다.
- 이전 버전·중복 알림은 같은 단계를 반복 생성하지 않는다. 실패는 재처리하고 확인이 필요한 건과 구분한다.
- 과거 상태가 늦게 도착해 현재 단계를 되돌리지 않게 한다. 실제 정정·재개는 사유와 전후 이력을 남겨 처리한다.
- CRM에서 사람이 다른 단계로 변경했거나 실주·부적합으로 종료했다면 충돌 검토를 거친다. 연동이 사람의 판단을 조용히 덮어쓰지 않는다.
- 연동 대상이 확정된 영업건에만 반영한다. 실시간 상태 반영이 전체 현장 일괄 변경을 의미하지 않는다.

## 4. 수주 유형과 금액

2026-10-04 사용자 확정: **매출실적은 아파트 공사금액 기준**이다. 첨부 기준의 확정된 공사·최종 낙찰금액(VAT 별도)을 금액 근거로 삼되 계약 체결 확인 후 인정한다. 기술자문료와 POUR 연결 계약금액을 더하지 않는다.

| 항목 | 기준 |
| --- | --- |
| 직접 수주 | 확정된 최종 낙찰금액 |
| 협약시공사 수주·기술자문 | 확정된 최종 낙찰금액. 기술자문료·POUR 계약금액을 더하지 않음 |
| 타사 이관 수주 | 사전 정식 보고 및 관리자 승인 조건을 충족한 낙찰금액 |
| 기술자문 계약금액 | 별도 연결 계약 금액 |
| POUR 계약금액 | 별도 연결 계약 금액 |
| 실행가·정산액·입금액 | 각각 시공·정산·대금 지표. 수주실적 대체 불가 |

- 영업 경로(브랜드), 영업 담당, 낙찰 시공사, 기술자문 계약 상대를 따로 관리한다. 브랜드를 낙찰 시공사로 취급하지 않는다.
- 첨부 예시: 낙찰 1,043,900,000원, 기술자문 433,650,000원, POUR 136,690,000원이면 수주실적은 1,043,900,000원이다. **이 예시는 운영 데이터 수정값이 아니다.**
- 원본 금액의 성격·VAT 포함 여부가 다르면 단순 비교로 일치 판정하지 않는다. 차이는 확인 대상으로 남긴다.
- 동일 영업건에 연결 계약이 여러 개 있어도 수주 건수·낙찰금액을 계약 수만큼 중복 집계하지 않는다.

### 실적 금액과 인정 시점

사용자의 “아파트공사금액기준으로 매출실적” 확인으로 금액 기준을 확정한다. 기존 **계약실적 — 계약 체결일 기준** 정책의 인정 시점과 이력 보존 원칙은 유지한다. 금액 기준과 인정 시점을 서로 다른 실적 지표로 나누어 중복 집계하지 않는다.

- 공사금액 10억 원, 기술자문료 1억 원이면 매출실적은 10억 원이다. 기술자문료를 더한 11억 원이나 기술자문료만인 1억 원으로 집계하지 않는다.
- 공사 계약 체결 완료·계약일·확정 공사금액·계약 당시 실적 귀속자가 확인됐을 때 인정한다. 시공·준공·담당자 변경으로 제거·이전·중복 인식하지 않는다.
- 공사 계약일이나 당시 실적 귀속자가 없으면 검토 대상으로 남긴다. 기술자문 계약일·준공일·현재 담당자로 대신 채우지 않는다.
- 변경계약과 취소는 기존 정책대로 적용일의 증감·반전 이력을 보존한다. 최초 계약·이력을 덮어쓰거나 삭제하지 않는다.
- 각 연결 계약의 원래 금액은 그대로 보존한다. 기술자문 계약금액 필드를 공사금액으로 덮어쓰지 않는다.
- 이번 요청은 운영기준 등록이다. 화면 명칭·디자인 변경, 과거 원장 재계산, 운영 데이터 변경을 실행한 것은 아니다.

### 기술자문료 정산과 인센티브

2026-10-04 사용자 추가 지시: “기술자문료는 각 영업사원의 정산금액-회사이윤 그리고 회사이윤에서 본인인센티브 가져가는구조”.

- 기술자문료 정산은 아파트 공사금액 기준 영업실적과 별도로 관리한다.
- 영업사원별 정산금액, 회사이윤, 본인 인센티브를 구분한다. 본인 인센티브는 회사이윤에서 지급하는 구조다.
- 위 문장의 정산금액과 회사이윤 사이 관계를 임의의 뺄셈식이나 배분율로 확정하지 않는다. 정산금액의 정의, 비용 차감 범위, 회사이윤 산식, 인센티브 비율·지급 시점은 사용자 확인 후 정한다.
