# 단계 1 — 문자 전달과 실제 발송 구분, 일정 교체 경로 보호

2026-10-11. **로컬 후보 / 운영 미반영 / 일정 보존 기능 OFF**.

## 1. 이번에 한 일

- 문의 상세의 문구 복사·외부 문자 앱 이동에서 응대 기록 생성과 후속 일정 등록을 제거했다. 외부 앱 이동은 발송 요청도 발송 완료도 증명하지 않는다.
- 카카오 선택은 기존 복사 기능을 유지하며, 버튼도 `카카오 문구 복사`로 실제 동작을 알린다. 카카오 앱 이동·특정 대화방 연결·자동 발송은 구현하지 않았다.
- 클립보드 실패를 성공으로 알리던 콜백을 고쳤다. 성공·실패 모두 작성 중인 문구와 선택한 템플릿을 유지한다.
- 현재 가운데 문자 패널, 이전 v3 문자 입력, 이전 v2 문자 입력에 같은 동작을 적용했다. 기존 요소의 동작 설명만 고쳤고 CSS·배치·크기·새 컨트롤은 변경하지 않았다.
- CRM에서 직접 발송하는 `crm_inquiry_sms_request_v1` 경로는 수정하지 않았다. 실제 발송 시험도 하지 않았다.
- 새 일정 보존 모드에서 예전 `contact_log`, `next_set`, `visit`, `quote_send` 쓰기를 서버 호출·로컬 변경 전에 차단했다. 진행 중인 새 저장이 있으면 플래그를 꺼도 예전 경로로 우회하지 않는다.
- 방문·견적 버튼의 저장 오류 시 입력을 유지하고 잠금을 푼다. 서버 연결이 없는 로컬 대체 처리도 새 모드에서는 차단한다.

문자 복사 수정은 기능 게이트와 관계없이 적용되는 버그 수정이다. 일정 교체 차단은 `CRM_SCHEDULE_V1`가 켜져 있거나 해당 문의에 미완료 새 저장이 있을 때만 적용된다. 플래그 OFF의 기존 일반 응대 동작은 유지한다.

## 3. 서버 필드·SQL

이번 수정에서 서버 필드·RPC·SQL 추가 없음. 이전 일정 보존 및 첫 응대 SQL 후보는 여전히 적용하지 않았다. 방문·견적의 기존 SQL을 새로 안전하게 만들었다는 의미가 아니다. 해당 두 기능은 새 모드에서 이용할 수 없으므로 지금 활성화하면 안 된다.

## 5. 남은 계약 — Claude 인수인계

현재 파일과 서버 계약에서 해결해야 할 기능 조건만 정리한다. 화면 위치·스타일·새 입력칸은 정하지 않는다.

| 경로 | 필요한 저장 계약 | 현재 제한 |
|---|---|---|
| 방문 예정·완료 | 선택한 일정 ID, 현재 버전, 고정 요청 ID, 저장 영수증. 선택 일정만 변경/완료하고 다른 방문 약속은 유지 | `inquiry-flow.js`의 `visit`는 재시도 식별 계약이 없고, 기존 SQL은 열린 방문들을 일괄 완료할 수 있음. 새 모드 차단 |
| 견적·발송·후속 | Claude 견적 v3 원본 버전·계산 결과·PDF·당시 수신자·발송 근거 연결. 발송 재시도 중복 방지, 후속 일정 재사용/추가 구분과 기존 업무 보존 | 기존 `quote_send`는 열린 업무를 교체하고 서버 미연결 시 로컬 완료 가능. Codex는 계산·PC 견적 구조를 대체하지 않음. 새 모드 차단 |
| 문자 수동 발송 확인 | 외부 앱 진입과 실제 발송 결과 확인을 구분하는 근거·수신자·시각 계약. 같은 사건 재기록 방지 | 복사·앱 이동만 제공. 확인 UI의 승인된 위치/입력 계약이 없으므로 임의 추가 안 함 |
| 내일 09:00 보내기 알림 | 기존 업무 보존과 정확한 시각 저장을 함께 지원하는 계약 | `due_on`만 저장하는 새 일정 계약으로 09:00 알림을 약속하지 않음. 예전 교체 방식은 새 모드 차단 |

방문·견적 저장을 차단한 것은 기능 완성이 아니다. 위 계약과 PC/모바일 결과 비교가 완료되기 전 전체 모드 활성화·배포를 진행하지 않는다. 사용자 승인 시안 포트 8766은 그대로 두었다.
