# 협약문의 완료 기능 연결

협약문의는 B2B 조재연 담당 업무로 운영하며, 공사 영업과 구분합니다. 처리 결과는 `협약완료`, `해결완료`, `종결`이고 메모는 선택입니다. 다음 행동이나 날짜를 요구하지 않습니다. 수주·계약실적·메이드율·인센티브를 생성하지 않습니다. 기존 담당자와 권한은 이 기능이 자동 변경하지 않습니다.

## 화면 연결 계약

이 변경은 디자인을 포함하지 않습니다. `crm.html`에 로드된 `window.InquiryB2B`를 승인된 화면에서 호출합니다.

```js
const state = InquiryB2B.state(inquiry); // pending / done / review / null
const result = await InquiryB2B.complete(inquiry, selectedResult, optionalMemo);
if (result.saved) {
  // 서버 조회를 갱신한 후 처리 완료 목록에 표시합니다.
} else {
  // 아직 완료로 표시하지 않습니다. 동일 명령으로 재시도할 수 있습니다.
}
```

`inquiry`는 서버에서 조회한 원래 `id`, `updated_at`, 분류·상태 필드를 포함해야 합니다. `updated_at`을 현재 시간으로 만들어 보내지 않습니다. 결과 선택만으로 저장하지 않고 명시적인 완료 버튼에서 호출합니다. `review`는 과거 배드핏·수주·전환 등의 별도 확인 대상이며 자동 재개하지 않습니다.

저장은 기존 인증 명령 큐와 권한 검사를 사용합니다. 동일 요청 재시도는 중복 저장하지 않습니다. 서버 응답 확인 전에는 완료 상태로 바꾸지 않습니다. `saved: true`는 CRM 저장 완료이며 `sync_status: pending`은 기존 문의 시트에 반영을 기다린다는 의미입니다.

## 서버 및 기존 문의 시트

- `sql/inquiry-b2b-completion.sql`: 인증된 완료 저장, 원문·담당자·첫 응대시각 보존, 완료 이력과 전달 대기열의 원자적 저장.
- `sql/inquiry-b2b-sheet-delivery.sql`: 서비스 역할 전용 전달 대기열, 임대·재시도·저장 전 재확인·결과 확인.
- `server/inquiry-b2b/sheet-delivery.cjs`: 헤더와 대상 한 행을 대조하고 진행상태·응대내용·다음액션일·종료사유 네 필드만 반영합니다. 일치하지 않거나 이미 종료된 건은 검토 대상으로 남깁니다.

운영 DB에는 위 저장 기능이 적용되어 있고 n8n 전달 작업도 활성화되어 있습니다. 1분마다 완료 대기열을 확인하며 대기 건이 없으면 시트를 읽지 않습니다. 새 잔디 알림 메시지를 발송하는 기능은 포함하지 않습니다. 기존 잔디 처리와 동일한 문의 시트의 결과값을 사용합니다.

Google 시트 읽기와 쓰기는 원자적 비교·갱신이 아니므로 같은 순간의 수동 행 수정까지 완전히 잠그지는 못합니다. 실제 고객을 임의로 완료 처리하는 검증은 하지 않았습니다. 전용 화면의 버튼 연결과 사용자가 승인한 실제 처리 1건의 종단 확인은 별도 작업입니다.

## 집중 검증

`tests/inquiry-b2b-client.test.cjs`, `tests/inquiry-b2b-completion.test.mjs`, `tests/inquiry-b2b-delivery.test.mjs`에서 입력·응답 계약, 권한·버전 충돌, 중복 요청, 원문 보존, 단일 행 반영 및 재전송을 검증합니다.
