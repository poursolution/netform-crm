# [단계 1] 재로그인 뒤 이전 견적 요청 응답 차단

## 한 일

모바일의 기존 견적 요청·공사 시기 저장에서 같은 계정으로 로그아웃 후 다시 로그인하면, 이전 로그인에서 시작한 저장 응답이 유효한 것으로 처리되는 문제를 수정했다. 수정 전 합성 브라우저 검사에서 완료 화면 1개가 나타나며 실패했고, 수정 후에는 다음 업무 저장과 완료 표시가 차단된다.

현재 공개 master 확인값은 `7ba66adfb11d048a2061bd0a3a4a4bf8352873a4`(#595)이다. 이번 수정은 기존 모바일 기능 후보에만 적용했다.

## 바뀐 파일

- `mobile-fields.js`: 메모리 안에서 로그인 전환을 구분한다. 폼 진입 때의 로그인 상태를 저장 전·단계 정보 응답 후·일정 응답 후에 대조한다. 같은 계정의 정상 프로필 갱신은 허용한다.
- `mobile.html`: 해당 스크립트의 캐시 버전만 변경했다.
- `verify-mobile-fields-safety.cjs`: 동일 계정 재로그인 관련 검사 5개 추가, 총 23개.
- 후보 패치 생성기·검증 manifest·이 문서.

## 추가·바꾼 데이터 필드 / SQL

서버 필드·SQL 변경 없음. 로그인 전환 표식은 클라이언트 메모리에만 두며, 기존 초안의 계정별 저장 키나 저장 형식은 바꾸지 않는다. 정상 새로고침 후 초안 복구가 계속 가능하다.

## 점검표 통과 / 미통과

- 견적 요청·공사 시기 저장 보호 23개 통과: 재로그인 전 폼 저장 차단, 늦은 단계 정보 응답 차단, 늦은 일정 응답의 화면 반영 차단, 정상 프로필 갱신 허용, 기존 초안·부분 저장 복구 유지.
- 방문→견적 요청 및 일정 변경 통합 15개 통과.
- JavaScript 문법 검사 통과.
- 기존 HTML 생성·그리기 함수가 기준 원본과 동일한지 확인했다. 화면 배치·스타일·Claude 시안 변경 없음.
- 합성 브라우저 검사이며 실계정 로그아웃·로그인, 운영 저장, 실제 기기 검증은 아니다. 서버가 이미 처리한 저장을 취소하는 수정도 아니다. 늦은 응답은 적용하지 않고 현재 로그인에서 서버 상태를 다시 확인해야 한다.

## PC와 다른 점 / 남은 항목

이 수정은 모바일의 `MobileFields` 기존 견적 요청·공사 시기 경로에 한정된다. 다른 PC·모바일 저장 경로 전체가 같은 보호를 완료했다고 주장하지 않는다. 견적 v3 서버 계약·9화면 대응표 미준비 상태는 이전 인수인계와 같다.

기존 17개 통합 검사 결과는 이번 수정 전 실행 이력이다. 이번 변경 이후에는 영향을 받는 위 2개 검사 묶음만 재실행했다. 운영 배포·SQL 설치·새 기능 게이트 활성화 없음.
