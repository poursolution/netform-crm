# 문의 할 일 재조회 정합성 — 2026-10-10

대상: 영업운영 CRM `poursolution/netform-crm`, 기준 master `eed6e0c158b9bc6f674808988963840f15574311` (#538).

## 재현한 문제

서버의 `next_action`을 읽어도 `applyOverrides`가 이 PC에 저장한 `nextActionObj` 등을 나중에 덮어썼다. 다른 PC에서 기한·내용을 수정하거나 완료해도 예전 열린 업무가 남을 수 있고, 반대로 예전 로컬 null이 새 업무를 가릴 수 있다. 합성 자료의 회귀 검사 7개 중 수정 전 5개가 실패했다. 실제 고객 데이터를 변경해 재현하지 않았다.

## 기능 수정

- 새로운 서버 번들에 `next_action`이 명시된 UUID 문의만 조정한다. 부분 조회·합성 문의·잘못된 응답은 보존한다.
- 해당 문의의 전송 중·재시도 대기·응답 불명 요청은 보존한다. 조회 기준시각보다 새 ACK가 있는 경우도 기존 값을 유지한다.
- 서버 조회를 적용하기 직전에 예전 할 일 별칭을 로컬 적용 대상에서 빼고 `recoveredNextActionDraft`로 보관한다. 응대 작성 내용·약속 판단·담당 변경 이력은 그대로 둔다.
- 저장된 업무 ID·내용·한국 날짜는 기존 `actionObj`가 서버 값으로 읽는다. 서버에 업무가 없으면 예전 업무를 되살리지 않는다. 서버의 날짜만 있는 후속 일정은 업무 ID를 임의로 만들지 않는다.
- 복구한 로컬 자료는 한 번 저장한다. 새 서버 쓰기·알림·n8n 호출·SQL·권한 변경은 없다.

## 범위와 한계

현재 PC의 공통 문의 번들 적용 경로에 한정한다. 진행 중인 저장의 낙관적 표시를 전부 없애는 변경이나 개별 약속별 독립 업무를 만드는 변경은 아니다. 디자인·HTML 구조·CSS·표시 위치·고객 원자료를 수정하지 않는다. 새 UI가 필요한 약속별 업무 관리와 복구 자료 표시 위치는 Claude 담당으로 유지한다.

로컬 회귀 검사와 브라우저 검증은 합성 자료를 사용한다. PR 검사·운영 배포 완료 여부는 별도 확인한다.
