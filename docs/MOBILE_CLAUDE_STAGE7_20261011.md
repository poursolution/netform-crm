## 연결 동작

- C의 기존 `견적 요청 등록` 업무에서 K-1을 열고 같은 영업건으로 돌아온다. 메모의 키워드만으로 해당 업무를 추정하지 않는다.
- K-3의 기존 주 버튼은 제출금액 확인 화면으로 이동한다. 선택한 수정본 ID·기준금액을 유지하며 계산·확정·발송은 실행하지 않는다. 하단 기존 안내 칸에서 이를 표시한다.
- K-5의 V1/V2 행은 해당 등록 수정본을 연다. 과거 V1 조회에 최신 V2 예시를 재사용하지 않는다. 목록은 공용 `ListPager`로 최대 20건씩 넘긴다.
- K-1 예시 공종·수량·날짜 선택 의도, K-4 예시 발송할 안 선택은 같은 계정·영업건·버전 범위의 임시 선택으로만 유지된다. 고객의 안 선택, 실제 고객 약속, 요청 접수로 기록하지 않는다.
- 수량 초안은 새로고침·뒤로·재진입 후 유지한다. 계정 변경·대상/버전 변경·오래된 선택을 차단하며 로그아웃 시 해당 초안을 지운다. 임시 보관 실패 시 현재 입력은 남기고 실패를 알린다.
- 기존 일정은 읽기만 한다. 재발송이나 고객 반응으로 업무를 추가·취소·완료하지 않는다.
- 승인 원본/렌더러/모델/흐름 모듈이 없으면 이전 모바일 UI를 대신 보여주지 않는다.

## 추가·바꾼 데이터 필드

서버 데이터 필드·표·권한 변경 없음. 제품 쓰기 API 호출 없음.

로컬 검토 초안만 `sessionStorage`의 `crm:mobile-quote-review:v1:<계정>:<영업건>`에 30분 보관한다. 공종 선택 ID·수량 문자열·날짜 선택 의도·안 선택 ID 및 대상 버전을 포함한다. 전송 대기 요청/저장 영수증/업무 완료로 집계하지 않는다. 시안의 상대 날짜를 실제 약속일로 변환하지 않는다.

## PC와 다른 점 및 미연결 부분

모바일 전용 금액 계산 없음. PC에서 저장한 `base_amount`·`submit_amount`를 구분하여 표시하도록 준비했으며, 현재 모바일의 실제 영업건 투영은 최신 견적 v3 필드를 충분히 반환하지 않는다. 누락 값을 예상금액이나 옛 `amount`로 채우지 않는다.

- 요청 생성·처리 상태·질의응답·앞당기기 승인 조회/저장 계약이 필요하다. 기존 `consulting.quote_request` 문자열과 내부 예정일은 공식 견적 접수·고객 합의를 증명하지 않는다.
- 같은 수정본의 기준금액·제출금액·기준 버전·PDF·안 A/B·당시 발송 수신자 조회가 필요하다.
- #596의 계산/수정본 저장 경로가 모바일 허용 목록에 연결돼 있지 않다. 서버 성공 응답 유실 후 같은 요청을 복원할 계약까지 확인한 뒤 연결해야 한다.
- 완성 파일 업로드·자료 묶음·실제 발송·반응 저장, 방문 완료 뒤 요청 생성, 간단/공법 견적의 편집과 계산·확정은 이번에 켜지 않았다.

따라서 **7단계 전체 완료나 운영 사용 가능으로 보고하지 않는다.** 8단계 음성·명함의 별도 진행 상태는 [8단계 보고](MOBILE_CLAUDE_STAGE8_20261011.md)와 그 후속 보고를 따른다.

## 질문 / Claude 인수인계

현재 9개 폰 프레임은 제공된 원본 안에서 구현할 수 있어 새로운 디자인 결정은 하지 않았다. 다음 연결에 필요한 사항을 기록한다.

- K-3 원본 주 버튼은 `고객에게 보내기`지만 v3 흐름의 다음 단계는 `제출금액 만들기`다. 현재 버튼 모양·문구를 유지하고 기존 하단 칸에 이동만 한다고 명시했다. 최종 문구는 Claude 원본에서 통일할 항목이다.
- 원본은 가산 방식 하나 선택이다. 서버의 복합 가산 지원을 이유로 모바일에 복합 선택 UI를 만들지 않는다.
- 간단·공법 폰은 항목 표시와 액션을 제공하지만 상세 입력/공법 선택의 추가 원본은 없다. 임의 입력창을 만들지 않았다.
- source44 K3/K5 매탄임광 V2의 **2.9억은 기준금액**이다. 다른 예시의 1.7억 가산 화면이나 이전 PC 예시 1.089억과 하나의 수정본으로 섞지 않는다.

서버 상세 조건은 `CLAUDE_QUOTE_MOBILE_SERVER_CONTRACT_20261011.md`를 함께 본다. 마지막 운영 카탈로그 조회 시점과 결과는 복구 후속 보고에 기록했다. 이번 날짜·페이지 연결 작업에서는 운영 설치 상태를 반복 조회하지 않았다. 인수인계서 작성은 Claude에게 메시지를 발송했다는 뜻이 아니다.
