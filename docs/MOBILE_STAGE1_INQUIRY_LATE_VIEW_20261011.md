# [단계 1] 문의 저장 응답이 다른 입력을 덮는 오류 수정

## 한 일

최신 공개 master `0b7852e8824abf3740bb12b10b227ee7e3f84c59`를 다시 확인하고 로컬 후보의 실제 모바일 화면에서 오류를 재현했다. 문의 응대 저장을 누른 뒤 다른 영업건의 결과 입력 창을 열면, 늦게 도착한 문의 저장 결과가 새 입력을 지웠다. 수정 전 검사에서는 `contact/false: late response replaced newer editor`로 실패했다.

저장 시작 당시의 입력 영역이 그대로 남아 있을 때만 성공·실패 화면을 그리도록 제한했다. 사용자가 다른 입력 창으로 이동해도 원래 문의의 서버 확인·저장 상태 반영은 계속한다. 실패 시 원래 문의의 복구 기록을 보관하고, 재진입하면 같은 요청 번호로 남은 처리를 확인한다. 결과가 불명확한 종결 요청은 기존 중복 방지 규칙대로 재전송하지 않는다.

## 바뀐 파일

- `mobile-inquiry.js`: 응대·일정·종결 처리 후 현재 입력 영역 확인, 화면을 떠난 경우에도 복구 기록 보관.
- `mobile.html`: 모바일 문의 스크립트 캐시 버전만 갱신.
- `verify-save-recovery.cjs`: 실제 문의 창에서 다른 영업건의 실제 입력 창으로 이동하는 지연 응답 6가지 추가.
- 이 문서, 결과 JSON, 후보 패치·검증 manifest·진행상태.

## 추가·바꾼 데이터 필드

없음. SQL·서버 함수·권한·판정 기준 변경 없음. 기존 문의 기록, 단계 진행, 다음 업무 명령 및 저장 확인 계약을 유지한다.
