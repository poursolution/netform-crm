# 코칭 첫 연락 대상 통일 — 기능 변경 및 Claude 인계

기준: netform-crm master `94dffbfe6b9207c329afc75d41c9afe4d936233f`.

## 이번 변경

- 목록은 `ExecWording.firstBefore(name)`으로 현재 첫 연락 대상을 읽지만, 코칭 창은 선택 기간의 문의에서 `!inquiryResponded`만 적용했다. 원자료와 기간이 같아도 이관 기록 확인·종결·영업 전환 처리 차이로 대상이 달라질 수 있었다.
- `rep-window.js groups()`도 목록의 `firstBefore`를 사용한다. 첫 연락 건수·실제 대상 행·코칭 지표·묶음 요청의 안내 건수는 같은 배열에서 나온다.
- 과거 연도에 배정됐더라도 현재 남은 문의는 포함한다. 삭제·종결·영업 전환·기술자문·중복 보관·과거 통화 기록 확인 대상과 연결 기록이 있는 문의는 기존 공통 함수의 판단대로 제외한다. 새로운 상태를 저장하거나 통화 완료를 추정하지 않는다.
- 평균 첫 연결 시간과 배정/응대 흐름은 계속 선택 기간 기준이다. 누적 대상 수를 선택 기간 문의 수의 부분집합처럼 설명하지 않도록 기존 문장의 계산 범위만 정정했다.
- `G.execWordingOff`를 끄면 목록과 마찬가지로 기존 기간 기반 경로를 유지한다. 서버 함수·칼럼·SQL·권한 변경은 없다.

## 검증

기존 `scripts/verify-rep-window-browser.cjs`에 합성 자료 검증을 추가했다. 현재/지난 연도 문의, 이관 통화 원문, 종결, 전환, 삭제, 다른 담당자, 기술자문, 중복 보관, 연결 완료를 섞고 목록의 대상 ID와 코칭 대상 ID가 같은지 확인한다. 연도/전역 필터 변경, 연결 기록 추가, 재배정, 0건, 끄기 스위치도 검사한다. 기존 저장 ACK·실패 복구·버튼·화면 크기 검증은 유지한다.

로컬 확인: `verify-rep-window-browser.cjs`, `verify-reps-b-browser.cjs`, `verify-reps-v2-browser.cjs` 통과. 합성 검사 통과는 운영 배포 완료를 뜻하지 않는다. 운영 건수는 배포 뒤 동일 시점·계정·조회 범위에서 다시 대조한다.

## Claude에게 남는 표시 작업

이번 PR은 배치·색상·크기·여백·카드·버튼을 변경하지 않는다. `신규 배정 · 첫 연락 전` 묶음 제목과 `신규 배정` 등 기존 명칭 중 누적 업무를 기간 실적으로 오해하게 하는 부분의 최종 명칭과 표시 위치는 Claude가 결정한다. 현재 대상과 기간 실적의 배치를 바꾸는 작업은 포함하지 않는다.

기존 인계서 `CLAUDE_COACHING_SCOPE_EVIDENCE_20261010.md`의 남은 과제도 유지한다: 단계 체류/활동 없음/자료 미확인 구분, 고객 약속과 코칭 약속 구분, 단순 단계별 건수 차이를 이탈로 해석하지 않기, 코칭 당시 대상 ID 고정과 완료 증거 연결. 이 PR은 이들까지 완료했다고 주장하지 않는다. 실제 담당자에게 시험 코칭·요청을 보내지 않는다.
