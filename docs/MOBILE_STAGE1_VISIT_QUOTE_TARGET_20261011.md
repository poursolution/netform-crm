# [단계 1] 방문 결과와 견적 요청의 영업건·계정 연결 보호

## 한 일

실제 모바일 앱을 합성 서버로 실행해, 방문 기록 저장 후 다른 영업건이 선택되면 이전 방문 메모가 그 영업건의 견적 요청에 들어가는 오류를 재현했다. 방문 저장 당시의 영업건 ID와 계정을 고정하고, 견적 화면 진입 및 저장 전후에 대조하도록 수정했다. 새 배치·입력칸·버튼은 없다.

## 바뀐 파일

- `mobile-entry.js`: 방문 저장 결과에 대상 ID·계정 보존. 견적 이어가기에서 검증하고 기존 안내 경로 사용. 검증 실패 시 방문 결과 화면 유지.
- `mobile-fields.js`: 견적 화면의 기대 대상 ID 확인. 견적 정보를 보내기 전 선택 대상을 검사하고, 응답 대기 중 대상이 바뀌면 다음 업무 전송을 중지. 원래 영업건 재진입 시 확인된 정보 재전송 없이 남은 저장 재개.
- `mobile.html`: 두 모듈 캐시 버전 갱신.
- `verify-mobile-visit-quote-flow.cjs`: 실제 모바일 앱·공용 journal을 사용하는 통합 검사 7개.
- 이 문서, 진행상태, 후보 패치·manifest.

## 추가·바꾼 데이터 필드

서버 필드·SQL·RPC·권한 변경 없음. 메모리의 최근 방문 저장 결과에 `deal_id`, `owner`를 보관한다. 기존 quote 복원 저장소와 작업 ID를 그대로 사용한다.

## 점검표 통과 / 미통과

| 검사 | 결과 |
| --- | --- |
| 실제 앱: 방문 저장 → 견적 메모·공사 시기 이어받기, 자동 업무 완료 없음 | 통과 |
| 다음 업무 실패 → 재진입 → 같은 ID 재시도, 방문·확인된 견적 정보 재저장 없음 | 통과 |
| 새 일정 모드에서 예전 견적 일정 교체 차단, 방문·기존 일정 보존 | 통과 |
| 방문 저장 후 선택 영업건 변경 / 계정 변경 | 각각 차단, 통과 |

| 견적 필드 저장 중 대상 변경 | 다음 업무 미전송, 원래 건으로 돌아와 재개, 통과 |
| 기존 견적 안전·복원 검사 | 18개 통과 |

| 견적 HTML·paint 함수 원형 유지 | 기존 검사 통과 |
| 실계정·실제 모바일 기기·운영 저장 | 미검증 |

이번에 실행한 브라우저 검사는 총 39개다. 외부 요청을 차단하고 합성 RPC·큐를 사용했으며, 운영 고객 데이터를 저장하지 않았다. 새 검사는 기준 앱의 `mobile.html`을 로컬 후보 파일로 덮어 읽는 테스트 서버에서 실행했다. 운영 배포 화면 검사가 아니다.

## PC와 다른 점

PC 기능·화면은 변경하지 않았다. 이번 수정은 기존 모바일 방문 결과에서 견적 요청으로 넘어갈 때의 연결 보호다. PC·모바일 견적 v3 전체 연결 완료나 공통 계산 검증을 의미하지 않는다.

## 질문·남은 연결

새 디자인 결정 없음. Claude 디자인과 8766 시안 그대로 유지했다. 견적 v3 서버 계약 및 최신 모바일 화면 대응표 확인은 이전 인계 문서와 같다. 일정 보존 모드는 OFF다. 원자적 견적 저장 및 영수증 조회, 실제 서버·권한 검증이 남아 있다.

로컬 후보만 수정했다. SQL 적용·GitHub 업로드·병합·운영 배포는 하지 않았다. 전체 단계 1 완료로 보고하지 않는다.
