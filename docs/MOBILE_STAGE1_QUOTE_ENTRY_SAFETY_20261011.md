# 1단계 — 방문 후 모바일 견적 요청 저장 보호

후속 보완은 `MOBILE_STAGE1_QUOTE_RECOVERY_20261011.md`를 따른다. 창 재진입 시 입력·확인된 저장·큐 번호 복원을 추가했다. 필드 저장 응답이 불명확한 경우는 자동 재전송하지 않으며 영수증 조회 계약은 여전히 필요하다.

## 1. 완료한 작업

현재 모바일 `MobileFields.quoteSheet`는 견적 요청 필드를 저장한 뒤 예전 `next_action` 교체 명령을 보낸다. 앞 단계에서 문의의 `quote_send`를 막았지만 이 영업건 경로가 남아 있었다. 새 일정 보존 모드에서는 첫 저장 전에 차단하고, 기능 설정이 첫 저장 도중 바뀌어도 뒤의 교체 명령을 보내지 않도록 했다. 이미 저장된 방문 기록은 건드리지 않는다.

일반 모드의 재시도도 보완했다. 단계 정보가 확인된 뒤 다음 업무 저장만 실패하면 단계 정보를 다시 저장하지 않고 같은 큐 요청 번호를 확인한다. 그 사이 입력을 바꾸면 원래 입력으로 확인하도록 안내한다. 처음 연 시점의 견적 예정일을 고정해 자정을 넘긴 재시도가 날짜를 조용히 바꾸지 않게 했다.

## 2. 바뀐 파일

- `mobile-fields.js`: 저장 전 보호, 확인된 필드 중복 저장 방지, 계정·영업건·단계·저장 필드 응답 검증, 다음 업무 ACK 검증, 예정일 고정. 기존 HTML 그리기와 스타일은 동일하다.
- `mobile.html`: 해당 스크립트 캐시 버전만 갱신.
- `verify-mobile-fields-safety.cjs`: 실제 렌더러와 클릭을 사용하는 합성 브라우저 검사.
- 본 문서·검증 manifest·누적 패치.

최신 master `939a1bec1485ac3c85434364de79e681bfdaac26` (#593)을 공개 API로 확인했다. 직전 확인 이후 변경된 `package.json`, `quote-calc.js`, `quote-excel.js`, `tests/quote-excel.test.cjs`는 이번 후보와 겹치지 않는다. Claude의 견적 계산/Excel 작업은 수정하지 않았다.

## 3. 서버 칸·SQL

새 RPC·서버 열·SQL·권한·허용 목록 추가 없음. 기존 `crm_deal_stage_fields_update_v1`의 실제 반환 필드(deal_id, stage_code, version, stage_context.to/fields)를 확인하도록 클라이언트를 보완했다. 다음 업무는 기존 OperationalAdapter의 ACK 검사를 재사용한다.

## 4. 검사 결과

| 검사 | 결과 |
| --- | --- |
| 모바일 견적 요청 저장 보호 | 11개 통과 |
| 기존 모바일 관리자 요청 복구 | 5개 통과 |

새 모드 및 남은 일정 저장이 있는 경우 첫 쓰기 0건, 방문·기존 일정·입력 유지, 서버 거절·다른 영업건·필드 불일치·계정 변경 시 로컬 확정 없음, 같은 요청 재시도, 저장 중 기능 설정 변경, 공사 시기 단독 저장 유지, HTML/paint 함수 동일 여부를 검증했다. 실제 서버와 고객 데이터는 사용하지 않았다.

## 5. PC·모바일 차이와 제한

이 수정은 기존 모바일 견적 요청의 보호이며 승인된 견적 v3의 9개 화면 연결 완료가 아니다. PC 견적과 서버 계산·원본 버전·최종화는 Claude 담당 범위를 유지한다.

단계 정보 저장 RPC에는 고정 operation ID/영수증 계약이 없다. **필드 저장 응답 자체가 유실되거나 창을 닫고 다시 연 상황까지 중복 없는 재시도를 보장하지 않는다.** 이번 보완은 같은 창에서 필드 저장 확인 후 다음 업무가 실패한 경우에 한정한다. 일반 모드의 기존 일정 교체 방식 자체도 변경하지 않았다. 전체 새 모드 활성화는 계속 보류한다.

## 6. Claude 연결 인계와 다음 작업

기능 계약이 필요한 항목: 견적 요청 생성/수정의 고정 ID와 저장 영수증, 선택한 기존 일정과 별도 추가의 구분, 기존 일정 목록과 버전 확인, 당시 첨부 자료 연결, 요청 취소와 방문 기록 보존. 이 계약을 받은 뒤 승인된 모바일 견적 화면을 연결한다. 새 위치·버튼·시안은 만들지 않았다.

로컬 후보이며 운영 SQL 실행·쓰기·발송·GitHub 업로드·병합·배포 없음. 8766의 Claude 시안도 수정하지 않았다.
