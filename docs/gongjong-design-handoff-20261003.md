# 공종 분석 디자인 적용 기록

## 고정 기준

- 사용자 제공 `Pipeline redesign proposal_공종분석.zip` 안의 `design_handoff_gongjong/README.md`, `공종 분석.dc.html` 및 사용자 확인 캡처를 따른다.
- 공종 분석 목록과 상세만 변경한다. 공통 셸, 필터, 다른 메뉴의 디자인은 유지한다.
- 진단 영역 340px, 목록의 금액 68px / 추정 210px / 맞음 56px / 편집 72px, 알약형 탭, 검은색 맞음 버튼, 촘촘한 행 간격을 기준으로 한다. 좁은 화면에서만 줄을 나눈다.
- 테스트용 화면의 현장·숫자는 합성 데이터다. 운영 화면이나 운영 적용 증거로 제시하지 않는다.
- 시안의 93건·60건 등은 하드코딩하지 않는다. 현재 사용자가 조회할 수 있는 데이터와 필터로 계산한다.

## 동작

- 동일 Site ID를 우선 묶는다. ID가 없으면 이름과 주소가 모두 일치해야 묶는다. 이름만 같은 다른 현장을 자동 병합하지 않는다.
- 그룹은 최대 금액 순, 그룹 안은 최신 등록 순이다. 상세에서 같은 현장 내 영업건을 전환한다.
- 공종 확정은 기존 Phase11 권한/버전/저장 경로를 사용한다. 공종군만 추정된 상태에서 세부 공종을 임의 확정하지 않는다.
- 같은 현장 다른 건과 선택한 세부 공종이 겹치면 `같은 공사 · 합치기` 또는 `다른 공사 · 그대로 확정`을 선택한다. 별도 확정 판단은 기존 저장 사유 이력에 남긴다.
- 합치기 성공 ACK 전에는 원본을 목록에서 숨기거나 금액을 차감하지 않는다. 분석은 기존 건의 금액을 한 번만 사용한다. 원본 Deal, 계약실적 및 단계는 삭제·이동하지 않는다.
- 새 합치기 SQL은 원본 견적 버전을 기존 건에 복사 보존하고 원본 스냅샷·요청·처리자를 별도 기록한다. 재요청은 동일 ACK를 반환한다. 공종 분석에서만 원본을 중복 집계에서 제외한다.
- 현장 ID 미연결, 부분 복합 공종만 겹침, 계약실적이 존재하는 건은 자동 병합하지 않는다.

## Claude 활용

- 기존 `OpsStore.ai('work_guess', ...)` 경로를 사용한다. 공종 분석의 AI 추천 버튼을 누른 경우에만 Claude를 호출한다.
- 입력은 해당 영업건의 공사명·문의 원문·활동 기록으로 한정한다. 같은 현장 다른 건의 공종/메모를 섞지 않는다. 연락처 개인정보도 별도로 보내지 않는다.
- 출력은 기존 공종표의 세부 공종과 근거로 제한한다. 사람이 `AI 추정 맞음`을 눌러야 저장하며, 중복이면 동일하게 합치기/별도 확정 판단을 거친다.
- `AI 추정 있음`에는 실제 AI 응답만 표시한다. 기존 키워드 추정을 Claude가 생성한 결과로 표시하지 않는다. 입력이 같은 저장된 제안은 해시를 확인해 재사용한다.
- 다음 활용안은 동일 영업건의 기록을 근거로 한 다음 행동 추천이다. 이번 변경에서는 다른 메뉴의 다음 행동 기능을 수정하지 않는다.

## 반영 상태와 검증

- 로컬 코드와 공종 분석 전용 SQL을 작성했다. 이번 작업에서 GitHub 업로드·운영 DB 설치·사이트 배포는 실행하지 않았다.
- `sql/gongjong-merge-v1-20261003.sql`을 운영에 설치하기 전에는 합치기를 완료 처리하지 않으며 화면에 미설치 상태를 안내한다.
- `scripts/verify-work-v2-browser.cjs`: 합성 데이터로 묶음, 다른 현장 배제, 해당 건 기록만 AI 입력, 추천과 확정 분리, 별도 확정, 합치기 ACK 실패/성공, 단일 집계, 상세, 다른 메뉴 편집기 유지, 시안 치수·버튼·좁은 화면 확인.
- `tests/gongjong-merge.test.cjs`: PGlite PostgreSQL에서 원본 견적 보존, 권한 검사, 버전 충돌, 재요청 중복 방지, 계약실적 보호, 부분 복합 공종 차단, 직접 테이블 접근 차단 확인. 기존 actor/행 권한 함수는 검증용 fixture이며 운영 권한 검증을 대체하지 않는다.
