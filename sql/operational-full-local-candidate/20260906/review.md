## Catalog-gated disposable fixture compiler

`build-staging-disposable-fixture.cjs` is an offline compiler, not a deployment or test runner. It requires the exact post-apply read-only catalog capture, validates target/schema/FK/ACL/manifest freshness, and emits deterministic run-owned setup, cleanup, and Storage API cleanup artifacts. The compiler refuses missing or wrong-project catalogs and never writes to Staging itself. Mutating scenarios formerly described as canonical snapshots now receive equivalent disposable rows; canonical rows remain source templates only.

The generated setup and cleanup are each one guarded transaction. Canonical synthetic Inquiry/Deal rows are template sources only; new rows use a unique run UUID namespace and `fixture_run_id`. Cleanup obtains any server-created Deal UUID only from the run's fixed receipt ACKs, clears the Inquiry/Deal cycle, and deletes FK children before parents. Storage cleanup is intentionally outside SQL and limited to the exact `crm-staging-e2e/<run-id>/` prefix.
